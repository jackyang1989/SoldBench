## 草案 A · 来源撤销与恢复

1. 值班人记录来源、权限版本/epoch、撤销时间、覆盖的用途和原始受控证据。先暂停新采集、拒绝当前失权分发，再启动清除。正常断源按 stale/expired 降级，保留权利版本。
2. 用合成测试 ID 检查 owner 历史、结果详情、主图、分享、匿名投影和导出。记录读拒绝的时间、清除条数及失败重试，列表不得包含用户令牌或上游凭证。
3. 在独立环境恢复旧 PG 和对象快照，核对迁移版本、账户删除标记、来源撤销标记和最新签名水位。核对未替换账本、待迁移和待清除任务，测量 RPO 和 RTO。
4. 在流量恢复前断言撤销和删除均不反弹、底层缺失返回受控状态、恢复重放不双结算。出现差异继续隔离，保留证据给独立复核者。关联 AT-005/039/046/047/048/056。

## 草案 B · 工单与对账

1. P0 使用最小权限识别对应来源/支付/请求。用户凭工单回执获知已受理、待证据、已解决。正文仅授权处理人读取，由后续工程实现到期清理、查阅日志及授权回复。
2. 付款回跳展示待确认。按渠道交易/订阅周期和实际结算对账，比较支付金额、币种、授予额度、退款及差异。受控重试绑定原事件与交易键，保留人工审批理由，重复执行不改原流水。
3. 运行验证包括失去回跳、模拟渠道回执迟到、至少一次入账、错商户/金额、客服权限隔离、退款争议与过期。真实费用、发票与退款义务由渠道及经营负责人确认。关联 AT-030/037/038/051/052/054。

## 草案 C · 开发者交付和版本

1. 构建生成 OpenAPI、路由实现状态、语言页面、示例和可安装 Skill。文档列出运行入口、凭据安全、日期/金额、分页、owner 和 scope、429/503、取消/过期、显式领取、免费复取和单结果导出。
2. 以全新账号从可见流程生成 key，使用占位配置运行三种示例，保留首个响应、请求 ID、显式 claim 收费和历史余额。重复同一 key 证明免重复计费。选定两目标 MCP 宿主独立验收，保存实际客户端版本。
3. 行为变化先更新契约与兼容策略；运行真实 HTTP 对照和跨版本回归。发布公告给出受影响操作、例子、时间、迁移和回退，避免直接移除已有支持面。关联 AT-019/020/023/024/045/050/057。
