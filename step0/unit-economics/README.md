# 完整成本与候选定价测算

TASK-008 的离线工具使用 Python Fraction 对所有金额和费率精确计算。金额输入单位为 USD cents，JSON 中以十进制字符串保存，套餐售价须为整数分。输出保留分子/分母，展示金额 half-up，满足目标毛利的价格下限向上取整到分。

```sh
python3 step0/tools/unit_economics.py step0/unit-economics/unmeasured.json
python3 step0/tools/unit_economics.py step0/unit-economics/scenarios.json
```

`unmeasured.json` 为实际数据待填表，缺项返回 INCOMPLETE，指标保留 null。`scenarios.json` 的乐观/基准/压力数字均为假设，$29和5%+$0.50沿用演算示例。实测输入需要受控证据引用，工具只计算所填数字，证据有效性由责任人核验。`target_margin=0.50`为演算目标，实际套餐、额度、费用和商业目标需签收。

## 输入口径

一个场景覆盖同一月份、同一付费客户群及其明确分摊的免费负载。`customers`为付费客户数，`billable_queries`为实际可收费的有效查询数，`payment_transactions`为实际支付笔数。查询收费规则继续为每有效标准查询最多1credit。

`costs`按唯一类别填完整总额。infra和access_license为月固定现金，network/compute/storage/other为月可变现金，maintenance/support为劳动经济成本。网络、计算、存储必须包含本场景分页、重试、免费请求、失败、低样本和陈旧请求产生的全部消耗。免费和失败费用在资源类目中只计一次，维护人工单列。按观察样本正文大小推算出的值保留 assumed。

实测时附资源明细，包含run_id、来源准入版本、成功/免费/失败分类、请求/页/字节、CPU和存储、重试、工时、费率及日期。避免把已经汇入资源类目的失败成本再次追加至other。许可费用按合同拆分，若含用量部分可在other中登记并附明细，固定部分仅登记固定许可费。

支付费按毛收入比例及交易笔数固定费计算，退款损失和税费漏损各用毛收入比例扣除，争议固定成本另列。假设退款时支付手续费仍损失，真实合同不同时先调整明确模型版本。支付渠道的含税/未税售价、代扣税和出款/换汇费用应统一到该口径再输入，不能直接套用网上费率。

## 输出口径

净收入等于毛收入减支付费、退款、税费漏损和争议。现金贡献毛利仅减可变现金，全成本毛利再减固定现金和劳动成本。单位完整成本以可收费查询为分母，包含所分摊的免费和失败消耗，零分母返回null。

候选价格下限要求全成本毛利达到target_margin。现金盈亏平衡客户数保持当前每客户负载、支付频率、免费失败分摊及单价不变，以固定现金除每客户现金贡献计算，贡献非正返回null。扩容和维护人数变化需重新建场景。

P50/P95和最差5%成本须由逐任务资源明细计算，当前月汇总工具只给加权总成本，不从三个假设场景推导真实分布。定价前还需同口径竞品采样和真实客户预算，来源稳定性由连续验证独立评估。
