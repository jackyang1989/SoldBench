# 完整成本与候选定价测算

TASK-008 的离线工具使用 Python Fraction 对所有金额和费率精确计算。金额输入单位为 USD cents，JSON 中以十进制字符串保存，套餐售价须为整数分。输出保留分子/分母，展示金额 half-up，满足目标毛利的价格下限向上取整到分。

```sh
python3 step0/tools/unit_economics.py step0/unit-economics/unmeasured.json
python3 step0/tools/unit_economics.py step0/unit-economics/scenarios.json
```

`unmeasured.json` 为实际数据待填表，缺项返回 INCOMPLETE，指标保留 null。`scenarios.json` 的乐观/基准/压力数字均为假设，$29和5%+$0.50沿用演算示例。实测输入需要受控证据引用，工具只计算所填数字，证据有效性由责任人核验。`target_margin=0.50`为演算目标，实际套餐、额度、费用和商业目标需签收。

## 输入口径

一个场景覆盖同一月份、同一付费客户群及其明确分摊的免费负载。`customers`为付费客户数，`billable_queries`为实际可收费的有效查询数，`payment_transactions`为实际支付笔数。查询收费规则继续为每有效标准查询最多1credit。

`costs`按唯一类别填完整总额。infra和access_license为月固定现金，network/compute/storage/other为月可变现金，maintenance/support为劳动经济成本。网络、计算、存储必须包含本场景分页、重试、免费请求、失败、低样本和陈旧请求产生的全部消耗。免费和失败费用在资源类目中只计一次，维护人工单列。按观察样本正文大小推算出的值保留 assumed。

实测时附资源明细，包含run_id、来源准入版本、成功/免费/失败分类、请求/页/字节、CPU和存储、重试、工时、费率及日期。避免把已经汇入资源类目的失败成本再次追加至other。许可费用按合同拆分，若含用量部分可在other中登记并附明细，固定部分仅登记固定许可费。

支付费按毛收入比例及交易笔数固定费计算，退款损失和税费漏损各用毛收入比例扣除，争议固定成本另列。假设退款时支付手续费仍损失，真实合同不同时先调整明确模型版本。支付渠道的含税/未税售价、代扣税和出款/换汇费用应统一到该口径再输入，不能直接套用网上费率。

## 输出口径

净收入等于毛收入减支付费、退款、税费漏损和争议。现金贡献毛利仅减可变现金，全成本毛利再减固定现金和劳动成本。单位完整成本以可收费查询为分母，包含所分摊的免费和失败消耗，零分母返回null。

候选价格下限要求全成本毛利达到target_margin。现金盈亏平衡客户数保持当前每客户负载、支付频率、免费失败分摊及单价不变，以固定现金除每客户现金贡献计算，贡献非正返回null。扩容和维护人数变化需重新建场景。

P50/P95和最差5%成本须由逐任务资源明细计算，当前月汇总工具只给加权总成本，不从三个假设场景推导真实分布。定价前还需同口径竞品采样和真实客户预算，来源稳定性由连续验证独立评估。

## 17 项待填输入的取样责任

观察窗口统一为同一 UTC 月或同口径试点期。实测原件编号写入 `evidence_ref`，每条输入记录来源、币种、汇总单位、日期和责任人。分渠道、报价与客户群分别测算。

| 输入键 | 单位 | 采样与证据 | 责任角色 |
|---|---|---|---|
| `customers` | 同一期间付费 owner 数 | 从合法确权的订单去重，列试点转化和续费群 | 经营、数据 |
| `billable_queries` | 有效交付数 | 从 charge/claim 关联快照，按 owner、窗、真实计费键去重 | 账本 |
| `gross_price_cents` | USD 整数分/客户/月 | 按实际成交价和已核报价分组，附税的口径及折扣 | 经营、财务 |
| `payment_transactions` | 支付笔数 | 依渠道已确认的交易和账单去重，保留退款另列 | 财务 |
| `payment_rate` | 毛收入比例 | 按实际结算明细还原比例费，剥离逐笔固定费 | 财务 |
| `payment_fixed_cents` | USD 分/笔 | 对同币种逐笔手续费与对账单核均值，异质渠道分组 | 财务 |
| `refund_rate` | 毛收入比例 | 部分及全额现金退款去重，分列已用权益 | 财务、客服 |
| `tax_leakage_rate` | 毛收入比例 | 对账中的税及依法承担的差额，回填计税主体与责任 | 财税 |
| `dispute_cost_cents` | USD 分/期间 | 原渠道争议、撤销、手续费和回收记录，已入退款的金额避免重复 | 财务 |
| `costs.infra_cash_cents` | USD 分/期间 | 服务器、DB 固定费用、备份固定配额和监控账单按分摊规则 | 运维 |
| `costs.access_license_cash_cents` | USD 分/期间 | 核准合同固定费，按期间计入 | 来源、财务 |
| `costs.network_cash_cents` | USD 分/期间 | 分采集请求、重试、图像和 API 输出计量 bytes×费率 | 运维 |
| `costs.compute_cash_cents` | USD 分/期间 | 采集解析、归一、首次计算/缓存、编解码和失败的 CPU/作业用量 | 数据、运维 |
| `costs.storage_cash_cents` | USD 分/期间 | 数据库、媒体、存储请求及副本按 GB·日和操作数 | 数据、运维 |
| `costs.other_cash_cents` | USD 分/期间 | 变量许可费、换汇/提现或邮件等按凭证单列，确认未入其他科目 | 财务、运维 |
| `costs.maintenance_labor_cents` | USD 分/期间 | 按适配器维护、值班、撤权清除和恢复工时×签收费率 | 工程、运营 |
| `costs.support_labor_cents` | USD 分/期间 | 按客服、退款、手动复核及对账工时×签收费率 | 客服、财务 |

**分摊和满额压力**。按首次查询/缓存、有效/低样本/失败/排队/陈旧/免费复取、返回 1/50/200、带图/缺图拆原始记录，免费用户与已付用户分开统计。每笔只汇入一次原成本科目。以计划满额用户、真实免费与失败比例做压力复算，同时报告有效查询 P50/P95 和最贵 5%。观察不同用量与付费数时使用可复核权重并保存范围。比例为零须有实测依据，无数据写 null。

**需求和决策**。按六客群完成 10–15 位真实访谈，记录可观察任务、实际/估计频率、现用费用、预算权限、价格条件与至少 3 份明确付费承诺的目标。记录试点范围和获准用途。经营负责人联同来源与财务选择报价、配额和收费时点，签出实际试点下的满额毛利和回测证据。现有 0.50 仅为演算目标。[访谈规程](../interviews.md) · [报价待决](../../audit/14_DECISION_LOG.md)
