# 执行与交接模板

每项记录贴回原TASK，在台账保留唯一负责人和状态。以下占位符必须用实际事实替换；尚未做的写NOT_RUN，不保留看似成功的默认例子。

## 1. 开工记录

```text
TASK-ID / 日期 / 执行者 / 独立复核者（未确定则待指定）
阶段和门禁证据：G0/G1...，关联verdict/签收引用
当前环境：Git有无/HEAD或文件hash，工作区改动，当前服务和隔离DB
原稿S/T/F、PAGE、AT、DEC：
前置已满足证据：
目标和不变量：
本次文件范围/共享文件协调：
验证计划：正例、负例、并发、失败恢复、浏览器（按适用性）
回退/恢复：应用版本、迁移前向修复、已有数据保护
阻塞与待决：影响、负责人、恢复条件
```

## 2. 完成/交接记录

```text
TASK-ID / 状态 / 负责人 / 结束时间
实际结果：行为前后差异，不只列文件
变更：文件/迁移/接口/版本；commit或实际文件hash
环境：测试DB名、账号类型、数据来源模式、时钟、配置脱敏摘要
检查：命令、退出码、用例数、PASS/FAIL/NOT_RUN与范围
证据：相对路径、sha256、截图/日志/对账记录
独立复核：人员、时间、实际复核项；未做保持待复核
未完与风险：具体可复现限制、相关DEC和TASK
回退：已验证步骤或尚未验证，不删除资金/用户数据
下一步：可以领取的TASK、还缺的证据、文件占用释放
```

## 3. 浏览器与集成证据

同一缺陷必须记录浏览器实际服务/数据库/身份和自动化环境差异。截图文件建议 `AT-035-result-empty-390x844.png`，包含route、viewport、actor类型、query/job ID脱敏、结果状态；操作记录从空用户/可见输入开始。预期阻断与BUG_OPEN分别标记，按钮灰色本身不是正确证明。

关键状态都要观察：空、加载、正常、<8、stale接受前后、expired、forbidden、202、402、429、网络失败及恢复。收款/邮件先在沙盒完成，真实验收另留证；不把模拟付款/测试邮箱工具结果算作真实送达和资金结算。

## 4. 阶段复核记录

```text
Gate：G0/G1/G2/G3/G4/G5
范围：TASK与AT
代码和配置版本：
实现者：
非实现者复核人：
抽样步骤和原始输出引用：
未解决问题及是否阻断：
结论：NOT_READY / FAIL / PASS（G0另按verdict的GO枚举）
业务签署：谁、何时、批准什么（工程复核不代替来源/资金批准）
```

## 5. 新需求或规则变更

写明触发用户需求、当前行为、目标行为、V1/V1.5归属、来源/权限/资金影响、DTO与迁移、版本、受影响AT/TASK、估算和恢复。不要因“多一些细节”自动扩为第二市场、团队、完整导出或预测产品。
