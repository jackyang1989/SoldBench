# 多语言与商业交付补充规格

版本1.0，2026-11-16。用户已明确首发英语＋简体中文，其他语言按需求扩展。本文及DEC-12覆盖原稿“英文界面、中文P2”的旧限制；不改变eBay美国站、USD价格口径、统计和计费规则。本文是开发输入，尚未实现或通过浏览器验收。

## 1. 语言、站点与金额分别处理

- 首发客户语言为`en`和`zh-CN`，默认英语；中文界面仍查询eBay美国站。品牌SoldBench、API字段/枚举、SKU/评级、query_id和错误code不翻译。
- 界面语言不决定来源站点、币种、时间窗口、源时区或用户所在国。所有价格和套餐仍明确USD；中文显示`US$58.00`，不能改成`¥58.00`或擅自换汇。
- 翻译版本用独立`translation_revision`管理，不改变parser/cleaner/engine/billing版本。真正修改数据/收费语义才升级相应业务版本。
- 原始商品标题、来源成色文本、证据保持原文；中文标签与标准成色说明可翻译。自动商品翻译不在首发，不将用户中文关键词暗中翻译并冒充精准同条件查询；匹配词典只按已验证规则工作。

## 1.1 后续站点与当地语言共同发布

用户进一步明确：后期增加站点时同步增加所需当地语言，语言就绪是站点发布条件。已支持的语言复用翻译目录，按站点补当地用词、格式、币种/运费说明和经审核的商业内容；不能机械地为每个国家创建一种新语言，也不能只开放数据、把本地化无限延期。

| 后续站点 | 同步语言交付 | 站点特有适配 |
|---|---|---|
| 英国 | 复用英语 | 英国用词、GBP、日期/时间与运费口径 |
| 德国 | 新增德语 | 德语界面/自有邮件/核心帮助与商业文案，EUR及源属性 |
| 法国 | 新增法语 | 法语完整流程、当地格式/源属性及商业内容 |
| 意大利 | 新增意大利语 | 意大利语完整流程及当地格式/源属性 |
| 西班牙 | 新增西班牙语 | 西班牙语完整流程及当地格式/源属性 |
| 加拿大 | 英语复用，法语同步准备 | 加拿大地区格式、CAD及英法版本用词审核 |

## 2. 覆盖范围及发布要求

| 面 | 首发双语范围 | 不完整时的处理 |
|---|---|---|
| 查价和研究 | 首页、查询表单、筛选、结果统计/明细/排除原因、本地重算、异步/余额/陈旧/禁止状态 | 任一关键状态缺译阻断该语言发布；不能中英混杂表达收费条件 |
| 账户和商业 | 注册、验证、找回、会话、删除回执、历史、用量、密钥、订阅/取消/退款说明 | 两语言完整用户路径；网页使用不要求创建API key |
| 帮助和信任 | 定价、方法、数据状态、支持表单、隐私/条款与必需的用户同意文本 | 商业和法律翻译由相应责任人复核；未审阅不能用自动译文宣称已获确认 |
| 开发者交付 | 双语quickstart、计费/异步/错误解释；OpenAPI字段和代码示例保持同一英文契约 | 中文示例运行同一接口；不得生成两套不兼容SDK/接口 |
| 自有事务邮件 | 验证、重置、已实现的账户/账务通知；主题、预览、正文、按钮、期限和页脚 | 双语模板均有纯文本版；验证/重置不得因语言改变TTL、token或重发次数 |
| 原创内容 | 首批10–20篇/页按既有总量，不要求每篇重复翻译；核心方法/商业页按上面双语交付 | 未译指南只显示英语并标明语言，不制造空中文页或假hreflang |
| 内部后台与供应商页面 | 自有运营后台首发可英语；支付门户/发票/供应商邮件语言以渠道能力为准 | 客户跳转前说明外部页面可能为英语；核对实际支持，不承诺自有双语能覆盖第三方 |

内部中文开发文档不等于客户界面已支持中文；机器翻译可作初稿，价格资格、stale、退款、取消和法律文案需人工复核。其他语言没有完成完整路径、翻译及审核前不得出现在可用语言列表。

## 3. URL、选择与SSR

1. 保留已有英文Web URL；中文使用`/zh-CN`前缀（例如`/zh-CN/results/:query_id`）。API、webhook和MCP路径不加语言前缀。两语言指向相同业务资源及owner权限。
2. 当前明确带语言前缀或文档语言段的 URL 优先（`/zh-CN/*`、`/docs/en/*`、`/docs/zh-CN/*` 等不主动跳转）；访问无语言前缀的网页入口（如 `/`、`/alternatives`、`/search`、`/docs` 等）时，服务端按 `soldbench_locale` 第一方 cookie 优先，其次按浏览器 `Accept-Language` 默认导向简体中文（`/zh-CN/*` 或 `/docs/zh-CN/*`）或英文，未知语言仍回退英文，响应携带 `Vary: Accept-Language, Cookie`。网页顶部导航提供下拉式语言选择器（`EN ▾` / `中文 ▾` 展开 `English / 简体中文`，不用国旗代表语言），Docs 全屏壳页面不重复放置语言按钮。
3. 第一方cookie`soldbench_locale`只保存allowlist语言（`en` / `zh-CN`），切换语言时同步写入，`SameSite=Lax`（HTTPS 下附加 `Secure`）、最长180天，不含身份或权限。首发不增加账户语言字段，不承诺跨设备偏好同步。未知/不支持语言回英语；尊重Accept-Language权重，q=0不选，zh-Hant不当作已支持繁体。
4. 切换保留安全的当前路径、表单内容、查询/作业ID和已加载研究状态；不重新提交查询、POST claim、扣费、创建分享或延长复用窗。中文与英文不能共用含用户状态的SSR缓存。分享token URL仍按原保密规则处理，不发送至第三方分析。
5. SSR与客户端使用同一解析后的locale/翻译版本，避免水合时闪回英语。HTML正确设置`lang`，标题、表单标签、错误摘要、读屏名称和图表说明一致本地化。
6. 真正存在且可索引的双语公共页采用自引用canonical、互相对应的hreflang和合适的x-default。私有结果、账户、分享、无质量保证页仍noindex；不因翻译扩大SEO数据公开范围。语言与地区版本遵循 [Google多语言说明](https://developers.google.com/search/docs/specialty/international/localized-versions)。

## 4. 文案目录和数据边界

建立单一`packages/shared/i18n`目录，按common/search/results/account/billing/auth/status/support/docs分域；同一语义用稳定key，不在组件中拼接句子。日期/数量/货币通过格式化函数和参数渲染，不能用翻译字符串做金额运算。复数和带链接文本用所选消息库的结构化能力；TASK-011锁库版本并验证SSR兼容，不自研通用翻译平台。

开发CI检查en/zh-CN键集合、参数名/类型和必需富文本节点一致；禁止原始HTML注入。用户内容始终转义。开发环境缺key明确报错；生产非关键未知消息可回英语并记录匿名key指标，关键流程缺译应在构建前失败，不能靠上线fallback掩盖。

日期显示必须可理解且标时区，不能改变服务端滚动窗口。优先用户浏览器有效IANA时区，未知用UTC并标明；不持久化为账户设置。日期精度为天的源数据不能渲染出虚假的时分秒。credit数量与money分开，credit不格式化成货币。

语言和显示时区不进入SoldQuery、查询canonical hash、candidate_set_hash或收费去重身份；相同owner/业务参数10分钟内跨语言仍复用同一query。统计先计算再本地化，禁止从`US$1,234.56`等展示文本反向解析账务金额。

## 5. API、错误及邮件契约

- REST/MCP的字段、code、details.fields.field/reason及诊断枚举稳定；`message`默认英语，客户端根据code和结构化details本地化。禁止解析英文message分支，未知code回通用错误并显示request_id。
- 非webhook接口可发送可选`Accept-Language`头。Web调用适配器发送当前明确locale；它仅用于自有通知/视图语言选择，不改变数据、权限或收费。当前JSON结构中的message仍默认英语，UI使用本地目录。
- 邮件创建时将解析后的locale、template_key、translation_revision写入现有outbox.payload；worker按入队快照发送，不按服务器默认语言。首次请求幂等决定的语言不被重试头改变；显式重发按原冷却/次数规则创建新通知并选当次语言。
- 邮件CTA回相同语言的安全内部路径，校验return_to；token单次/TTL/日志裁剪不受语言影响。短信、营销订阅和额外通知不因本规格自动进入V1。
- 注册/找回仍按原泛化响应防枚举；支付渠道错误映射到自有稳定code，不把供应商原始隐私/内部错误直接翻译后展示。
- 首发不新增locale DTO或SQL账户列。请求头、outbox元数据与翻译目录是展示/通知契约变更，OpenAPI文档版本升至1.2.0；旧英文合成响应仍有效。

## 7. 商业产品的最小界面闭环

修正原稿§10的旧路径：网页用户注册/验证后可以继续查价，不必创建key。API用户才进入key→示例集成。两条路径分别做空用户验收。

结果页信息顺序：查询对象/属性和价格口径→数据时间/样本局限→价格摘要与可比数量→可追溯成交列表→过滤/排除诊断→用户调整与恢复。pending、空、低样本、stale、expired、forbidden、402、429和网络失败的动作按页面规格执行，显示布局不替代后端状态。

能读取完整计算输入时可用同一输入辅助解释价格分布；只得到四分位不得编造直方图、市场销量、趋势或预测。任何新增图形都给实际样本数、口径和文本替代，不新增收费统计算法。图片和高级筛选属于独立功能评审，不以“商业系统”名义默默扩大范围。

支持请求已有API-30；必须显示受理编号、查询关联与恢复状态，后台按最小权限检索和审计。尚无客服回复时效证据，不宣传全天候人工支持。账务补偿、现金退款与来源纠错沿用既有受控流程，不能让支持人员直接编辑钱包或权威价格。

## 8. 验收与实施归属
