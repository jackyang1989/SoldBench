## 2. 字段可得性先于解析实现

每个获准入口必须有字段能力表和实际原文证据：listing ID、独立event key/身份依据、是否售出、售出日期和时区/精度、sale format、actual/displayed/unknown price、currency、shipping及适用目的地、condition、版本/评级/型号属性、页标识/下一页/排序、来源更新时间、允许保存和公开范围。

对每字段登记 `available_verified / available_unverified / unavailable`、原文位置、解析规则版本、缺失语义。没有字段不通过猜值补齐：

- Sold标记不能证明页面展示金额就是议价成交金额；有明确核验依据才verified_actual。
- 商品结束未必售出；推荐商品、广告、相似商品不得混入已售候选。
- unknown shipping不是0；免费运费需要明确依据；目的地不同不得说是所有人的到手总价。
- listings/items sold/transactions/events不是同一数量单位，解析时保留来源计量单位。
- 多件库存累计售出数、重刊、重复抓取不能被展开成虚构的逐笔事件。
- 缺成交日期/时区/事件身份则保留诊断，按冻结资格规则排除统计。

评级卡牌若缺评级机构、等级、版本、语言或卡号等强约束证据，必须说明不具备该查询所需精度。GameBoy合成fixture不证明评级卡牌入口可用。

## 3. Collector管线与持久化边界

`plan → permission guard → budget reservation → fetch → classify response → parse → validate → dedupe → commit observation/events/outbox → advance watermark`。

每次请求前再查当前权限、熔断和预算。只有所需页面成功完成、字段资格已校验、存储事务提交后才推进水位。中途失败可保存明确partial观测，但不能把整查询覆盖时间更新为now。恢复从已提交checkpoint继续，页cursor必须绑定query/排序/来源配置版本，不跨参数复用。

任务持久化字段：run_id、source/config/clearance revision、corpus/query hash、mode、fixed as_of、deadline、page cursor、committed checkpoint、planned/attempted requests、bytes/pages、lease/version、terminal outcome、stop reason、parser/schema版本、可留存证据hash。没有原文存储权只留被允许的摘要。

调度按已批准源速率和每日预算限制；初始并发1。优先服务已有开放类目的刷新，避免冷门新查挤占全部刷新容量。不能通过无限重试/增加机器/新增账号提高“最终成功率”。

## 4. 重试、失败分类与恢复

| 类别 | 自动动作 | 结果/恢复 |
|---|---|---|
| DNS/连接超时/临时5xx | 最多初次+2次，指数退避+抖动，遵源更低上限，受总deadline/预算约束 | 耗尽failed；保留最后有效快照，不推进水位 |
| 429 | 遵Retry-After及许可；超过deadline则停止/后续有界排期 | 计入首次失败和成本；不能换出口 |
| 401/403/挑战/登录墙/明确停止通知 | 立即open circuit；停止受影响源排队任务的外发 | 人工核验权利和入口后探针，禁止自动绕过 |
| 200但错误页/登录页/验证码 | 响应分类器判失败 | 不能记成功/空成交；同上停止 |
| 页面结构/关键字段不符 | quarantine并暂停受影响parser | 离线样本修复→人工复核→获准小流量探针 |
| 正常空结果 | 需要明确的空态结构且query/filters/locale对应 | 可记有效空结果，但不计有价可收费查询；known-positive突降触发质量告警 |
| 重复页/cursor循环/异常页数 | 停止，标partial和pagination_loop | 不制造重复事件，不标完整 |
| 存储/数据库失败 | 不确认完成，不推进水位，依幂等恢复 | 重放不重复event/outbox |
| 任务取消/过期/旧lease | 提交CAS拒绝 | 不生成新charge，不覆盖新worker结果 |

默认网络超时、总任务deadline在PoC配置中显式记录，线上值受批准方式与实测约束；15秒是API同步预算，不是所有采集任务必须15秒完成。合法慢任务走202，后台仍有明确期限与资源上限。

## 5. “稳定”指标与分母

| 指标 | 分子/分母 | 原稿基线及判定 |
|---|---|---|
| 调度执行率 | 实际启动的获准计划任务/冻结计划任务 | 必须报告；漏调度不从分母删去 |
| 首次语义成功率 | 第一次请求即可取得符合query和结构的结果任务/计划有效任务 | 原稿总体建议≥95%，每开放类目≥90%；逐日逐类目及头尾分组，不只14天均值 |
| 有界最终成功率 | 预算/deadline内成功任务/计划有效任务 | 必报独立于首次；不得靠无限重试美化 |
| 关键结构完整率 | 满足该记录类型必需字段schema记录/该类型解析候选 | 原稿≥99%；合法unknown允许表示，不能误充verified |
| 核验价格可用率 | 合格实际价格事件/可比事件 | 独立报告；“字段有值”不代表实际成交价已核验 |
| 可收费结果率 | fresh、权利有效且n≥8的结果/全部有效查询 | 单列热词/长尾/类目；不能以HTTP成功率替代 |
| 新鲜数据覆盖率 | 当前fresh的预定可售查询/预定可售查询 | 必报分母、采样时点及24h内断档；不承诺全市场覆盖 |
| 数据正确性 | 抽检误标actual价、错型号、重复事件、漏页、日期误判 | 价格伪核验/重复造事件在回归集中必须0，线上发现立即关闭受影响结果 |
| 成本和维护 | 全请求/失败/重试/页/CPU/存储/许可/人工费用 | 按成功、可收费及免费结果分别摊；重度客户压力门不省略 |

新鲜覆盖率/最终成功率的正式商业SLO必须由实测和产品承诺共同确定，未定前每日原样报告，不能先写“99.9%”。既有网站API≥99.5%可用性不代表eBay新数据可用性。源码版本更新前后分段报告；不能删去故障天使14天连测看起来全绿。

**G0**：原稿五门全部通过；只过HTTP可达不算。源准入、actual价可得性、身份/日期、楔子质量、成本和用户需求有任何根本缺口保持NOT_READY/NO-GO。上线前仍须生产型Collector7天观察和完整账户/计费断源测试。
