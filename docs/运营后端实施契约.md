# 支持与运营后端

TASK-034/035 离线工程。所有运维命令拒绝Bearer API key，以浏览器会话校验当前角色、近期认证、管理员MFA、同源与CSRF。support只能读脱敏摘要，不能写。管理员命令保存幂等、原因摘要与审计。真实来源、付款和发信关闭。

- 支持入口接收有限类别、最多4000字符的用户消息和可选请求ID。按网络地址的HMAC窗口限流与幂等入库，不记原始IP。无异步邮件动作。后台摘要不返回支持正文、账户身份或账务私有凭据。
- 公开状态只返回本机服务与数据模式，不写“真实行情正常”。来源列表、作业/账本/审计须经角色校验，隐藏凭证、搜索词、详细错误、供应商对象与原始消息。
- 来源命令只对当前synthetic offline_fixture生效。暂停用既有熔断，撤销同时更新来源权限epoch与媒体清理outbox。probe只检查本机配置/准入/预算及已有采集证据，记录结果，不重开熔断或派发请求。不同命令用来源ops版本做CAS。
- 作业重排只允许原owner仍有效、原快照可读、失败可重试、无领取/计费、未超过到期及尝试预算的本机查询。保留原查询/作业身份，不增加采集请求。采集原始artifact仍走现有Worker规则，后台接口不重放第三方流量。
- 额度补偿复用BillingService、原charge与不可变流水，全程在同一owner和操作者权限事务内。重复返回同审计记录，不能生成现金退款。
- 恢复控件由当前管理员权限启用。`/operations` 的作业、对账、付款恢复使用现有受控命令，操作人填写原因，付款恢复还要填写工单引用。`GET /admin/recovery` 要求近期管理员 MFA，只列出已耗尽确认重试的合成收据摘要。证据尚缺则保持原状态，存在更新或冲突的事实进入人工复核。响应中断时在原表单用相同内容重试复取原审计编号。列表仅显示收据 ID、已尝试次数、渠道和接收时间。

支持正文和回复拒绝 NUL 与未配对 Unicode 代理项。每个实际网络对端每小时最多 8 个成功新申请，幂等复取沿用编号。当前本机保留期 30 天，Worker 分批删除过期工单、回复及幂等记录。后台队列和审计只返回必要状态和脱敏引用，工单正文经指派和审计读取。上线还需确认正式人员、留存、投诉机制和 SLA。

## 值班受理、投诉和下架（2026-11-18 补充）

S2、AT-051/052、TASK-034/035。`POST /support/requests` 对接受的请求返回 202 和 `request_id`，须带 `Idempotency-Key`。网页同时生成 32 字节随机私密回执，以 `X-Support-Receipt` 提交和查状态，数据库只存域分离 HMAC。响应丢失时原内容、键和回执可取回原编号。普通工单号没有状态读取权限。`GET /support/receipt` 只返回本工单状态、最新回复和时间，保留期结束或账户删除后统一不可用。

`/operations` 的支持工单页读取脱敏队列。近期 MFA 管理员领取时登记 UTC 截止时间，原处理人失去资格后其他合资格管理员可接手。正文、关联请求和最近回复仅由当前处理人读取并记录审计。管理员可提交回复、关闭和重开。状态变更使用条目版本和幂等键，回执只显示状态和最近一次公开给请求人的回复。外部通知、自动超期提醒及正式人员和服务时限仍需批准与实测。

|---|---|---|
| 已受理 | 创建工单号、类别、UTC 接收时点、必要的 request_id 与隐私等级；保留一个重复提交键。客户端超时同键重试；429 按 Retry-After 再试 | 双语显示编号和可用的下一步。受理仅表示已收件，响应时限由实际负责人签署后展示 |

**下架与数据质量处理**按影响收敛：

1. 当班人登记权利依据的受控引用、来源/字段/用途、对象、有效时间及工单。可信撤权通知触发即时止读；未明范围的投诉先交权利负责人，按可识别风险隔离，避免将所有技术性无数据误记为撤权。
2. 管理员近期 MFA，在合成环境读取 GET /admin/sources 的当前 version；POST /admin/sources/{id}/commands 发送 command、reason、evidence_ref、version 及有效幂等键，保留 command_id/audit_id。响应丢失时同键同内容复取，收到 409 后重读状态，由操作人判断是否需要新命令。suspend 用于技术异常，revoke 触发权限 epoch 变化和清理，probe 只读检查准备情况并记录版本。真实源命令尚未交付，真实场景用经批准的隔离/停分发措施并留存证据。
3. 记录阻断生效时间与每种副本清理时间，交叉核私有结果、历史明细、媒体、导出、分享、缓存和恢复后读链。先拒读，再清理。撤权后的复开须有新授权和有效版本；后台重排、探针和切回旧服务都不能恢复旧许可。
4. 按关联工单向有权接收人反馈处置范围、时间、仍在处理的副本及下一更新时间。现金异议另走支付规格，API 补偿只修复相应 credit。需要跨系统恢复时按[发布、回滚与撤权恢复手册](发布、回滚与撤权恢复手册.md)。

**验收**使用匿名和登录合成用户各提交一次，唤起去重、超时取回、429 与到期清理；再以支持、管理员未做近期 MFA、管理员三角色走账单异议和撤权。AT-051 要求可追到处理人、时限、动作、回复/未能回复原因；AT-052 要求 support 写入被拒、CAS 冲突不产生第二个命令、不同 owner/匿名用户无法读他人信息。设施/人员/双语页面未完成前，两项继续保留相应待验范围。

### 2. 管理界面、角色和版本

- 内容中心呈现类型、搜索、筛选、草稿/已发布版本、维护人、最近更新时间、双语完成度与待签收项。详情可查看差异、预览桌面/移动与英中、被哪些页面引用、发布历史和审计。设置和审批显示变更对象、生效范围、影响、原因、当前版本和执行结果。
- 现行 support 权限保持只读脱敏。内容编辑/审校按专项能力授权，编辑可保存草稿、预览和送审；发布、回滚和敏感运营变更由具备相应授权的管理员执行，写入时复验会话、近期 MFA、同源与 CSRF。计价/法律/来源等需对应负责人签收。高风险变更保留提交者与审批者独立身份及决定记录。原型 support 可以编辑草稿的演示须落在明确授权的内容编辑能力中。
- 每项配置具有稳定 ID、环境/站点、内容类型、两语字段、状态、版本、时间窗、作者、审核记录和受控证据。服务端持久化草稿和不可变已发布版本，PG 为当前生效指针与审计的事实源。编辑采用版本比较，冲突保留各自的草稿并提示重新比较。浏览器可保存视图偏好，站点内容、人员权限和已发布版本均以服务端为准。

### 3. 发布、失败恢复与停用

1. **保存草稿。** 校验字段、格式、允许值、slug 唯一、引用、受众、时区及起止。英中必需字段未齐列出待补。配置编辑与用户查询、付款和采集队列相互独立。
2. **预览与送审。** 预览只允许授权会话，双语使用同一草稿版本，带明显草稿标记，禁止索引和公共缓存。记录差异、影响页面、测试结果与必要审批。缺签收、断链、无类别权利或无有效报价时阻止发布。
3. **发布或排程。** 发布校验当前版本并在事务内保存发布版、切换生效指针与审计记录。定时任务到时再次检查权限和前置，以稳定业务键去重。并发、重复请求或响应丢失可取回原操作结果。失败时维持上一个生效版本并保留草稿、准确错误和重试入口。
4. **交付与核验。** 前台从公开投影读取同一生效版本，发布后刷新缓存并验证新会话、英中页面和关联路由。保留版本、UTC 生效时间及操作编号。缓存短暂失效时继续用仍获准的已发布内容或明确状态；权利撤销、已下线政策、报价失效与禁用业务动作即时依领域守卫，避免从旧版本恢复。
5. **撤回或回滚。** 从历史选择经当前校验仍获准的版本，记录原因，作为新发布操作留痕。排程可取消，已发布内容可归档，错误页更新缓存/索引。回滚内容不能撤销已提交领域行为；账本、权限、来源、账户删除按原领域恢复手册执行。

### 5. 当前可操作的内容发布（2026-11-19）

从 `/admin/content` 进入内容中心。当前管理员会话和近期 MFA 是读写前置，支持角色无法读取草稿或调用命令。输入公告、FAQ 或指南的稳定标识及两个语言的标题和纯文本正文。草稿创建不可变修订，修改继续创建新修订。通过送审后，由另一位已认证管理员批准，再发布到首页、`/faq` 或 `/guides`。一致的 PG 生效指针驱动两个语言，无需重新构建。可按曾发布的版本回滚，或撤下当前版本。命令必须填写原因，沿用幂等键时返回原审计编号；过时版本的命令返回 409，已开始的草稿可复制后比较最新版本。

### TASK-060 运营审批和个案

普通账户暂停及恢复采用独立申请、审校和执行。申请保存当时的凭据版本，执行重查两位操作者的管理员与 MFA 状态、目标非运营账户、当前状态与版本。暂停撤销原会话和 key，恢复需重新登录和签发凭据。支持角色继续使用已有脱敏工单、账本及审计，可接收面向其权限的概要。用户 360 及内部笔记限近期 MFA 管理员，删除账户时清除内部笔记和审批事由，同时保留不可写回身份的操作记录。事件按独立记录追加审计，公共状态以领域数据为准。实际资金执行、紧急来源撤回、正式运营授权均沿现行契约。

### TASK-061 运营监控读侧

报告界面读取本机最近 1–30 天的记录，覆盖状态读取截至当前的水位。采集异常率以已结束运行作分母，纳入失败和取消。快照质量数量按快照相加，同一成交可能出现在多个快照，数量用于定位工程质量。成交抽查按来源与事件查找，标题和主图同时绑定原观测，逐次检查字段、留存和权利。API 分组只使用现有留存日志，金额和主图 URL 不进入聚合。买家转化、留存、市场覆盖和经营成本缺真实观测时均为未知。阈值写入只改变本机告警报告，不改采集器行为、公共健康或线上值班配置。Rules 展示运行版本及采集见到的解析版本，发布和回退需要真实兼容性及发布审批。

身份冲突触发隔离后，成交抽查省略受影响事件，快照质量排除含该事件或已过留存期的快照。运行轨迹继续保留已记录的停止原因和计数，便于追查故障。

采集监督进程以持有来源锁的数据库会话记录检查、派发、等待和正常停止。每个来源保留最新阶段、上个完整轮次的队列计数、最近一次自动健康报告的状态及检查时间，以及最近一次实际主图维护的状态（`idle` 无到期项、`processed` 已处理清理、`backlog_pending` 积压待续清、`store_unmatched` 媒体目录未匹配、`failed` 失败）及检查时间。普通轮次不抹除上一条维护记录。Collector 运营页显示当前工作、推进截止时间、目录状态、缺包和未检查分母。本机 Monitoring 只对当前获准、仍有推进期限的监督进程统计超时。尚未观测的来源保留未知，已停止或失权的来源显示停止并保留历史观测。主图清理单独统计已到期且未完成的撤权任务，包含撤权来源，并投影最近一次主图维护状态与检查时间（旧记录或未批准字段值显示未知，不暴露私有目录或源证据，撤权清理是否完成仍以 `outbox` 为准）。Collector 运营页显示各来源任务数和最早到期时间，实际完成后清除告警。该报告只涉及状态与聚合计数。

Collector 运营页的“刷新计划”表可按来源过滤。待登记计划数统计当前已到期且游标未推进的计划；最早未登记时段也可为未来。待派发数统计已经登记、仍在等候或正在领取的时段，逾期数计其中已到截止时间的部分。已入队但缺包的作业继续在“采集监督”表显示。上轮计数来自最后一次监督记录，尚无调度观测显示未知。

“刷新计划”还显示上轮从积压中优先登记的有效时段数。“采集证据快照”读取对应时间窗内当前来源权限版本的最新本机报告。采集监听进程按十五分钟间隔补快照，也可用 `npm run collector:report -- --source=UUID` 手动生成。页面显示快照时间、观测窗口、时钟口径、计划分母、首次页面派发、准时派发、仅领取及主图观察分母。来源失权、时间窗内没有合格报告或旧报告缺字段时显示未知。模拟时钟以单独标签展示。该读侧不重跑采集、不写快照，也不输出原页、主图地址或私密信息。

“响应包入站”显示上轮实际扫描项、已恢复包、暂缓包及是否需要续扫。按来源过滤，旧版本未记录的列显示未知，实际记录的零保持零。入站报告只投影计数，响应目录和文件内容仍为内部私有资料。
