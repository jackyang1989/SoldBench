# 竞品能力实施规格与路线图

版本1.0，2026-11-16；依据用户“开发前必须补进计划与排期”的明确要求，按DEC-13执行。本文件定义功能交付与验收；任务负责人、状态、E窗口、人日、证据仅由[开发排期与任务台账](开发排期与任务台账.md)维护。竞品事实与官方链接见[逐页核查及差距盘点§8](竞品核查与差异化建议_20261116.md)，公开宣传未经生产性能实测。

## 1. 发布范围与执行顺序

首发V1：面向六类客户的完整eBay US成交研究产品，英语/简体中文；必须覆盖查价、明细主图、详情证据、统计分布与重算、单结果导出、账户/支付/用量/日志、REST/Playground/MCP/Skill/双语开发文档、后台支持与故障恢复。首发所有适用验收未通过，不能通过“后续补齐”发布。

V1.1：OAuth/Passkey、批量CSV工作台、历史档案、Best Offer后查；已有正式任务与工程预算，可按技术依赖提前做离线工程，实际发布必须通过专项前置。V1.5：收藏提醒、UK/DE、图片/条码查价、库存估值。V2：第二平台、卡牌/评级、拍卖、其余eBay站点。运费报价和RapidAPI渠道有单独决策交付包，未采纳前不纳入现有套餐。移动App/SSO/多席位/预测仍不因竞品比较自动成为已授权范围。

历史档案的留存权利评估、覆盖账本与可删机制必须在首发数据模型和存储生命周期预留；获准后从首日归档，不等历史接口开发完成才存。没有许可的数据不归档。后续排期内的工程完成不创造历史数据、合法权利或额外国家语言覆盖。

整包顺序继承ADR-13：工程数据核心→账户查询账务及详情/日志服务→网页与支付→MCP/完整开发者交付与运行验收→扩展包。真实来源准备可贯穿开发，但真实请求及发布各按门禁。用户专业HTML原型供视觉实现；领域服务、DTO和页面状态卡先交付。不得因等待设计而搁置数据和流程契约。

## 3. 首发新增功能的开发细节

### 3.1 详情、证据与导出（CP-07/09）

入口是Search每条成交的详情抽屉，以及开发者详情/导出操作。请求只接受当前owner已获准结果中的sale_event_id，不接受任意上游URL。先复用已入库证据，不因打开详情直接触发网络或扣新查询credit。返回字段包括身份、型号/版本/容量/评级/成色、可获准描述、缺陷说明、核验状态、纳排理由、观察/成交时间、来源与当前可见图片；每字段区分未采到、无权展示与未知。主图首发必交，多图只有来源明确允许才展示，无图不隐藏成交。描述当作不可信文本处理，去脚本/外链追踪，不执行原站HTML。

单结果导出先选“权威结果”或“Your adjusted view”，注明全量/截断、快照ID/hash/版本/时钟/币种/价格口径/列定义/排除理由，不能把手工调整导出标为权威统计。CSV防公式注入；不含上游图片URL、私有对象key、owner标识/账户字段；导出重查当前权利并有大小/时间限制。无权分发返回明确错误，单结果下载不新扣查询credit。HTTP方法、owner边界、schema和错误先在TASK-028更新契约，AT-059覆盖真实Web及API流程。

### 3.2 账户安全、日志与文档（CP-12至17）

V1用户可启用TOTP，绑定需再次认证并验证一次性口令，恢复码只展示一次、哈希保存、单次使用；停用/重置安全审计并撤销受影响会话。管理员强制MFA，找回不能经客服直接绕过。Passkey和OAuth单列后续任务，不把“有key登录”写成OAuth已完成。

请求日志展示时间、入口Web/API/MCP、request_id/query_id/job_id、状态/错误code、耗时、复用/stale、credit结算结果及ledger引用。详情请求/轮询与新查分开，不同入口都调用共享用量服务；分页过滤、账户隔离、敏感参数裁剪、保留期与删除按隐私规则。Support从空态到提交/收件编号/失败重试可用；真实邮件在资质与供应商到位后验证，不预填成功状态。

文档目录覆盖quickstart/auth/sold-search/detail/pricing-evidence/jobs/pagination/errors-retries/credits/media/Playground/MCP/Skill/status/changelog；英文与简中共用契约生成参数和错误表。提供Python、TypeScript和curl的200/202→claim→免费复取→usage样例以及429/额度不足/503分支。样例CI基于合成服务，不用真实key。交付`.well-known/skills/index.json`、SoldBench `SKILL.md`及references、llms.txt/llms-full.txt、openapi.json；文档搜索不能检索用户私有结果。Changelog说明增加/修复/弃用/收费口径影响及迁移办法，不能直接复制竞品变更。

## 5. 防止漏项的发布检查

首发CP-01至18逐项链接实现提交、AT证据与独立复核，CP-04/09/10/12/16中明确后续部分不作V1已交付声明。所有六类客户的首发目标流程必需功能都要过门，不能只看API成功。CP-19至24按版本实施，各包内部仍先冻结来源/功能/接口/费用/错误/验收，缺其中一项不得进入生产集成。

[文档检查器](check_docs.py)检查24个CP均有合法TASK与AT，新增需求必须同步本表、功能规格和台账。它只检查追踪完整性，不证明功能已实现、数据可得或达到竞品质量。开发中发现新事实及时修订任务和预算，不能为了称“规划无缺口”隐藏未知外部条件。
