# SoldBench 项目审查与优化建议

日期：2026-11-15。依据：完整阅读原始 v1.4、复算 121 条夹具；参考 qcwarehouse 的 AGENTS、PRD、开发规格、任务台账和 E2E 证据格式。没有检查不存在的产品代码；以下区分已发现的规格问题与尚未实现的能力。

2026-11-16整改更新：以下表格保留首次审查依据；GAP-01/02/03/04/05/06/07/08/09/12/13/14的通用契约已由ADR-12、完整OpenAPI/SQL及页面规格补齐，测试设计已落盘。它们的产品实现与真实数据验证仍待执行。GAP-19中的真实许可、账号/审批/域名证明继续缺失；不能将技术规格完备当成稳定数据源。

## 1. 结论

2026-11-16竞品复核补充：SoldComps.io与sold-comps.com是不同供应商；公开文档已覆盖多项原先设想的差异化能力，不能再将中位数/四分位、清洗、未知议价价排除或MCP单独作为独有优势。实际供数、严格属性匹配、完整可用样本及可复查证据应形成独立对照验证。详见 [竞品核查与差异化建议](竞品核查与差异化建议_20261116.md)，当前未进行付费调用或独立性能测试。

项目已经有完整的产品方向、差异化判断和数据真实性原则。最需要补的不是更多市场、图表或 AI 功能，而是把“来源→事件→可比集→统计→返回→收费→恢复”的规则变成明确契约，并证明来源可持续及满额用户不亏损。生产实现应严格留在原稿 GO 之后。

本轮采用 qcwarehouse 的“功能/页面→接口与状态→任务依赖→用例→实测证据”组织方式；没有搬用仓库订单、质检、Stripe、Next.js 或对方已有进度。

## 3. 夹具复核发现

- 121 个不同 sale_event_id；64 条可比；58 条有核验实际价；6 条仅展示价；57 条型号强不匹配。
- 全候选最近 30 天 98 条，可比 41 条，符合价格资格的 35 条；原稿使用 35，不能在仪表盘误换成 98 或 41。
- 58 条价格 Type 7 得到 median=5800、p25=4200、p75=7600，双端各去 2 条得到 trimmed_mean=5930；不是 10% 截尾。
- 58 条核验记录字段较齐；另 63 条缺少 listing_id/currency/condition_std/sold_date_precision 等生产字段。该文件适合统计测试，不能直接当成生产 sale_events 导入格式。
- 合成 source_id、没有真实许可/原始成交证据及有效来源链接；不能据此标记来源核验、匹配精度、线上稳定性或商业 GO。
- 原文件保留；离线复核用 Fraction 精确计算。详情与 hash 由 `step0/tools/verify_fixture.py` 输出。

## 4. 优化顺序

**现在做**：按已冻结收费/时间/身份规则开发离线验证，准备准入/质量/成本证据模板、离线 Collector/统计验证、补 120 查询语料与人工标注规程。当前正式代码工作为零不是缺陷，是原稿的阶段要求。

**GO 后首先做**：来源权限与数据层、单一规范化查询、确定性价格引擎、可重放 outbox。账户/计费必须在数据和质量门通过后进行。先用评级卡牌的版本/评级正反例证明价值，Game Boy 是跨类目统计回归。

**上线前必须做**：真实空账号走查、独立 API 客户端、100 并发余额/幂等、Redis/Worker/Collector 故障注入、来源撤销、付款退款对账、恢复不复活已删数据、两 MCP 客户端联调。页面测试不得预填隐藏状态绕过操作。

**有证据再优化**：慢查询索引、缓存策略、队列优先级和资源预算按实际 P95、长尾成本调优；PG16 不分区，先不建微服务。SEO 控制为 10–20 个有证据页面，收藏/提醒/CSV 保留后续。
