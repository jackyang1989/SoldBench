# 搜索页采集字段与统计契约

版本1.0，2026-11-16。依据用户提供的两张CompSniper Search截图逐项核对；截图只证明界面显示及页面自身说明，不能证明其后台来源、完整性或实际性能。本文补全DEC-13、[竞品能力实施规格](竞品能力实施规格与路线图.md)和[采集稳定性专项](采集稳定性专项规格.md)，不表示已获得任何真实字段。来源字段清单全部保持未核验。

## 1. 核对结论

初查时，现有核心字段/黄金统计已覆盖价格、运费、时间、成交方式及部分属性；主图有离线安全原型。仍未满足完整搜索页：原来源字段表遗漏标题/链接/图片/卖家等；SoldQuery缺少价格范围、成交方式和展示排序参数；普通均价/运费摘要/卖家计数/近期时间序列/分组统计没有正式返回契约；成色缺原站ID与地区/品类映射；手机和Mac属性模板未建立。离线实现已覆盖HTML证据落库、受控主图、REST研究详情、逐条诊断和JSON/CSV，并交付价格范围、成交方式和多数补充统计。§8记录本次实际强属性验证；来源字段及主图商业授权、生产映射和电子产品专项模板须继续验收。下表保留截图初查的差距与TASK映射。

区分原始采集、系统计算、用户输入、产品账户数据。**不要抓取竞品统计卡数值充当SoldBench数据**。所有统计基于完整、同过滤、同快照的合资格集合，limit只控制返回条数。无来源许可依然0外网；字段缺失不得用0、相似图或推断价格填补。

## 3. 必须采集与存储的补充

`step0/source-capabilities.csv`登记采集字段的availability/evidence/parser/missing semantics；权利不由此表授予，另在source_clearance字段权限登记。sale_event_id是SoldBench内部事件身份，不要求源页面天然提供同名ID；必须有独立身份依据才能建立核验事件。

新增字段组：title、listing_url、condition_id、condition_raw、condition_mapping_context、displayed_price、accepted_offer_evidence、shipping_status、shipping_evidence、shipping_context、primary_image_candidate、primary_image_role、primary_image_evidence_binding、primary_image_dimensions、seller_source_identity、seller_public_handle、source_reported_match_count、source_reported_match_count_context、source_record_unit、query_capture_context、item_specifics、condition_description、description、gallery_images、field_visibility_permissions。

所有新增字段先记unverified。每条原值有capture时间、来源/页/记录定位、parser版本、保留期限与字段许可；无法保存原文时留允许的hash/定位摘要。图片许可分别覆盖保存/变换/展示/分发，图片状态由媒体生命周期决定。

卖家数据最小化：不采姓名、邮箱、电话、地址、联系方式。只有明确权利允许时持有平台公开seller标识/handle；用于去重的源内伪名引用也须有相应处理/保存权利，不把哈希当免责。公开handle属于可选字段，默认不公开，无权/缺失显示“不可用”；seller count缺失时null或明确“已识别X，另Y未知”，不返回假0。身份仅在相同来源/站点上下文去重，不跨平台合并人。

手机候选属性：brand/model/generation/storage_gb/carrier_lock/region/condition；Mac候选属性：family/model_year/chip/cpu/ram_gb/storage_gb/region/condition。接口接收attr前必须在对应taxonomy schema注册、定义别名/单位/未知语义并通过金标；现有六类目没有手机或Mac专用模板，用户例子不自动解锁这些品类。缺强属性不能仅由标题泛词猜值。

保留Open Box、Refurbished、Parts Only等原站成色标签；standard condition依品类/站点/映射版本转换。Open Box不自动等于like_new，零件/故障可单独查价但不得混入正常完整商品统计。现有标签new_with_tags等不能直接套用全部电子产品。

## 4. 新增过滤、排序及计费契约

规划扩展SoldQuery：`min_price_cents`/`max_price_cents`可省略，非负安全整数，min≤max，包含边界；`sale_format`可选fixed_price/auction/best_offer。范围作用于当前price_basis对应的**已核验USD价格**，未知实际价在诊断保留但不进入价格筛选有效集合。它们进入语义hash及缓存/owner复用身份；更改条件先明确是新查询并服从既有10分钟复用规则。对全候选先筛选再算统计，limit最后应用，不能只筛前50条。

展示排序是同一已交付快照的presentation参数，`sold_at_desc`默认，可选title/price/shipping/total/date/condition/seller的升降序；null始终末尾，稳定次键sale_event_id。只对完整可获权集合排序再分页/截取；仅有已加载子集时明确“仅排序已加载记录”。排序/切Table-JSON/导出不采集、不重算查询费用、不改变candidate_set_hash，不能因URL参数排序重扣。OpenAPI1.5.0已将范围/format加入SoldQuery，展示sort仅放在已交付结果GET；normalizer现已支持新过滤，sort不进入新查SoldQuery。core evaluate支持presentationSort；HTTP结果读取仍未接通，不能描述为线上可用。

用户可查看原始候选/全部诊断与可比集；切换诊断视图不解除强属性/未知实际价/身份资格限制，不能点一个“关闭AI”就把错误型号变成默认有效价格。泛词iphone/Mac mini混多代型号时先展示“包含多种型号，请细化”与可选属性；可以给明确的混合样本描述，但不能把混合中位数称为具体型号的参考价。

## 5. 计算口径与展示资格

以下是TASK-020/028的`supplemental_stats`数据字典（共享core与OpenAPI1.5.0已提供离线实现/设计，待持久服务交付），与现有SoldStats分离以保留旧黄金字段；新增schema/fixture/engine版本后才能对外。每项应有value/status/sample_count/eligible_count、unknown_or_withheld_count和口径说明；卖家身份不满足许可时不能仅为了卡片完整而采集。

- `mean_cents`：完整n_price_verified的普通平均，整数有理数求和最后half-up；n<8为null。另保留`trimmed_mean_cents`，不把trim标为Average。
- `shipping_summary`：只在当前可比且已核验商品价集合中、统一目的地/服务上下文且运费已观察或明确免费者计n_known；免费金额为0参与平均。n_known≥8才给mean_shipping_cents；免费比例free_count/n_known同时给分子分母，n_known=0为null。不同上下文分组或返回不可比，不混合平均。
- `seller_summary`：同一当前可比集合中允许处理的稳定seller标识去重；同时给可识别记录数/unknown/withheld；全无依据value=null，不能拿行数当卖家数。公开名字与聚合权利分别校验。
- `recent_30d`：固定as_of最近30天合资格集合median；`previous_30d`：紧邻之前30天。二者同过滤/币种/price_basis/日期规则，均至少8条且均有可比覆盖证据才给delta=(recent-previous)/previous；previous=0或覆盖不足为null。返回原始分子/分母便于复算；没有60天可用数据不画百分比。
- `by_format`：fixed_price/auction/best_offer分别给n与median；**每组n<8中心为null**。Best Offer只有verified_actual参与；展示挂牌价组仅诊断，不能取它的median冠名实际成交价。补图右侧6条BIN/1条Best Offer不满足SoldBench中心统计门槛。
- `time_series`：30D初始按UTC日桶、90D按UTC周桶，All只对本快照真实窗口；桶有start/end、n、median、date precision、coverage_status和partial。每桶n<8→median null，空桶n=0与采集缺口/未知覆盖分开；缺口不补0、不平滑插值连线，必要时用户选择按周汇总。日精度跨桶边界不明者保留未分桶计数，不能伪造秒级成交时间。改变图表周期不执行新查，需更长窗口时先确认并按正常查询处理。

近30/90天已观测样本趋势属于首发结果研究，不等于TASK-046的多年档案/完整历史承诺。没有足够桶就显示记录分布和不足状态，不为了有图强行给一条绿线。分布图每个bin同样注明样本与口径；平均/趋势/分组都不可替代原质量五分项。

原始搜索匹配数用`source_reported_match_count`及reported unit/exact_or_estimated/context/as_of表达，许可不足或不可得则null。该数不是样本统计分母，不能用来算coverage.ratio、成交总销量、售罄率；截图的“9 results of 210,000”不能推出覆盖率。API返回内部计时不采信竞品耗时；缓存命中与实时执行分别标注。

## 7. 当前离线实现与剩余边界（2026-11-16）

`packages/core`现提供价格/格式规范化、过滤完整候选/排除对账、稳定展示排序、普通mean、按context分组运费/免费比例、许可seller引用去重、最近/前期30天median、coverage不足/前期0抑制环比、UTC日/周桶和format独立小样本门槛。normalizer/engine为1.1.0，旧黄金SoldStats字段不变，supplemental_stats为独立补充，OpenAPI1.5.0允许追加此字段并有合成fixture。

coverage输入只可来自相同查询/快照获准collector观测水位，不接受用户伪造；complete只指计划来源观察，绝非全市场覆盖。change_ratio输出有符号金额分子/正金额分母，避免过早百分比舍入。运费groups含context_ref/known_count/mean_shipping_cents/free_count/free_share，顶层含unknown_or_withheld_count/mixed_contexts；只明确verified_free_shipping计入免费笔数，观察到数值0不自动变成免费声明。seller_summary只接收上游已按当前许可过滤的opaque sellerRef，包含distinct_count/identified_count/unknown_or_withheld_count。

时间序列用UTC日/周桶，桶同时有窗口、样本数、median、观测覆盖和partial。UTC整日证据只有完整落桶才分配，跨日或边界不确定保留unassigned_count；没有秒级来源不会伪造秒。日精度区间在一次分析内预计算，避免每桶反复执行时区推导。

主图/卖家/成色等生产持久化字段、真实source证明、账户/查询/claim/结果DTO运行交付、网页图表与CSV仍未完成。单元结果不等于AT-074/075全链验收。旧快照不补写新统计，版本升级后新生成；旧fixtures保留原设计版本用于兼容检查。

## 8. 显式强属性和详情证据

- 查询带 `category`、`brand`、`model`、`condition` 或 `attr_*` 时，逐笔核对同一 `sale_event/listing/source/observation` 的冻结结构化证据。类目、品牌、型号和类目属性使用命名属性，成色使用显式的标准值。比较仅做NFC和两端空白规范化，区分大小写，不猜标题、不跨观察借字段、不把Pre-Owned一概映射为good。没有明确条件的查询仍保留既有基线清洗。
- 已确认不符记 `hard_attribute_mismatch`。未看到必要证据记 `missing_strong_attribute_evidence`。同时触发时，确认不符优先。两者归入原硬属性排除计数，不进入统计与额度判断。保留逐笔诊断，修正冻结候选和hash，同一authority供API、MCP、重算和导出。历史cleaner 1.0.0的非显式筛选结果仍可读取，旧显式筛选结果停止交付，须以现行规则提交新查询。已付请求遵循原10分钟复用保护。
- 合成HTML profile可显式配置 `conditionStandard`、`description` 和 `defects` 选取；详情为最长2000字符的纯文本，须同条记录来源、独立字段权利。旧无此字段的profile和v1证据继续可读。缺证返回missing，撤销返回withheld。不发源HTML或把缺陷文本当作平台核验结论。生产适配须另外核验这些字段及取得对应权利。
