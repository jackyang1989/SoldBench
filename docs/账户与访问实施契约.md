# 账户与访问实施契约

2026-11-17，TASK-023/024/025离线实施，继承ADR-12/13、AT-031/032/033/055/060。完整账户与密钥领域供Web/REST/MCP复用，真实发信/来源/支付及公开发布不解锁。

认证/安全命令重试按[ADR-14](adr/ADR-14.md)，修正初始OpenAPI把收费Idempotency-Key误复用到登录/单次token的歧义。MFA/重新认证旋转session与CSRF，绝对到期不延长；API key明文仍仅首次创建/旋转返回。

密码采用Node22标准crypto.scrypt（N=131072/r=8/p=1、随机16字节salt、64字节key），不是自行设计密码算法；编码参数固定，KDF并发有界。邮箱小写/NFC/trim，密码不trim/不做隐式Unicode归一。token/key/session使用32字节随机数、分用途HMAC哈希与恒时比较；数据库不保存明文密钥。会话7天绝对期限，管理员12小时；每次读检查用户/凭据版本/撤销/到期；敏感写要求10分钟内重新认证，MFA用户同时要求近期MFA。Cookie HttpOnly/SameSite=Lax，生产须Secure；当前仅loopback HTTP开发，禁止生产启动。

所有Cookie写请求校验准确Origin与X-CSRF-Token，登录/注册/邮件令牌等匿名写也必须来自准确Origin，不接受宽松CORS或通过API Key管理账户。会话CSRF由token域分离派生，不成为另一条登录凭据。Bearer与Cookie同时出现拒绝，API Key按owner/scopes校验，不能调用会话/账户管理。普通登录/验证/找回/发信有PG时间窗限速，错误不泄露其他用户数据。

验证token24h、重置30min、单次消费；重发60秒/每账户每小时5次。邮件内容及一次性token用独立AES-GCM key加密保存私有outbox，公共outbox只有message ID/locale/revision；模板英/简中入队即冻结，不说已真实送达。注册及重复邮箱均返回accepted，不自动建立会话，符合现有Accepted契约；找回/重发始终accepted。验证成功设置free_anchor并产生唯一email_verified事件，100credit由后续统一billing服务发放，不在auth复制钱包规则。

查询 worker 每轮可处理一封事务邮件，冻结模板经本机队列状态 `queued_offline` 转到 `ready_offline`。同一数据库事务记录内部 outbox 回执。重发、消费、到期与删号后，旧消息立即失去预览资格，维护轮次或删除事务清除密文。状态 `ready_offline` 只说明可用本机工具预览。队列和预览按用户、令牌和邮件加锁，并校对用途、有效期和账户状态。

离线运维用 `npm run auth:mail -- --list` 获取最近可预览的消息 ID、用途和语言。`npm run auth:mail -- --preview --message=UUID --output=/private/path/message.json` 由显式操作创建 0600 文件，拒绝覆盖，标准输出仅给回执。输出文件含一次性链接，应留在私有测试目录。`npm run auth:mail -- --once` 可手动处理一封。没有公开预览路由、SMTP 或外部邮件供应商，外部送达仍按 DEC-08。

TOTP由锁定otplib实现，secret加密、绑定10分钟有效、确认后启用；登录未完成MFA的会话只能做MFA/退出。当前步±1容差且last_used_step单调推进，防重放。恢复码10个高熵码，仅首次展示、只存哈希、单次使用。密码找回不删除MFA；安全变更撤销受影响会话，管理员禁止关闭MFA。MFA setup/确认/关闭/恢复码接口先纳入冻结OpenAPI，不能把不存在的旧契约当已覆盖。

用户/会话关联的MFA、确认、重新认证及改密还按owner独立限流，计数事务先提交，错误proof不会回滚次数；跨多个IP也不能绕过。当前管理员角色每次读重算MFA要求，角色提升后旧会话立即受限；首次管理员可用待MFA会话绑定。改密/重置同事务撤销该用户尚有效reset_password tokens，不能用旧链接重置新密码。每用户至多20个有效会话，超额撤销最旧；绝对TTL不因reauth/MFA延长。

本地开发API首次启动在`.local/auth-secrets.json`生成随机secret并以0600保存，重启复用；不提供仓库默认密钥。生产启动仍拒绝，不把该文件替代生产KMS。旧admin_mfa表保留，未自动解读/迁移其密文，当前管理员须在新user_mfa验证后才有MFA会话。真实迁移、KDF容量和送达需单独验收。

API Key创建仅展示一次，列表无明文，最多20个有效key、唯一scope白名单；创建/撤销/旋转需近期会话认证+CSRF。旋转同事务撤销旧key并建新key，不保留可恢复明文。幂等创建/旋转只保存请求hash和key ID，重放返回已有ID且不再次展示secret，遵KeyCreatedReplay。账号停用即时拒绝，撤销每次查PG即生效；不依赖Redis作为权限事实源。

用户行→会话/令牌/MFA/key→审计/outbox固定锁序；KDF在事务锁外执行，入事务复查原hash/凭据版本防并发改密登录。测试包括空账户、重放/过期、恢复码并发、密码重置与登录竞争、跨owner、CSRF/Origin、停用/撤销、模板locale和真实本机HTTP；不把离线邮件算送达。追加SQL迁移，保留旧数据/迁移，不把整个TASK/G3写完成。

密码参数依据[Node22 crypto](https://nodejs.org/docs/latest-v22.x/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback)与[OWASP密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)，TOTP依据[otplib官方](https://github.com/yeojz/otplib)。部署前需实测KDF资源预算及外部安全复核。

## 账户安全网页入口补充（2026-11-19）

`/account/security` 调用现有会话、近期认证、改密、TOTP 安装和恢复码接口。安全操作以服务端最新 Session/CSRF 为准，明文 TOTP 密钥、恢复码仅在当前操作页面出现。浏览器测试绑定真实合成 TOTP、执行近期认证，再使用已有删除接口。`/deletion-receipt` 以 `X-Deletion-Receipt` 读独立回执状态，页面地址不携带凭据。底层会话和凭据约束仍按本文及 ADR-14。
