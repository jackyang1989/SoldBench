# 账户删除与恢复保护

TASK-039 本机账户子交付。保留 ADR-12/13、近期认证与现有不可变账本。此工程只作用于专用本机 PostgreSQL；生产保留周期、退款/争议法定义务、备份外部保管和生产RPO/RTO另签。

- POST /account/deletion-requests 要求近期认证、当前会话、同源/CSRF 和显式 confirm。客户端先独立生成32字节随机回执，服务端以域分离HMAC存储，有效30天。回执通过独立请求头读申请状态。响应丢失时不必知道申请ID，可用同一回执访问固定查询路径。回执不允许读取账户、恢复登录或查询结果。
- 接受事务立即将用户标为deleted、清空联系方式/密码，撤销会话/key/share，撤下其已发布匿名缓存并停止未交付计算。数据库保留不含个人正文的删除tombstone和收据哈希。正常客户端无法再提交该用户数据。真实支付终止尚依渠道许可，离线订阅标为期末结束。
- Worker分批清掉账户私密认证材料、查询正文/参数、结果/诊断、分享和可识别支持文本，保留财务/审计只读关联。每批与checkpoint原子提交，恢复后重复执行不复活私有数据或修改计费流水。
- 恢复前必须撤出流量。本机恢复包 `soldbench.offline-recovery.v2` 在同一 PG 一致性快照读取账户删除标记、来源权限摘要、允许继续使用的会话、API key、认证令牌、分享与匿名快照发布。值班人须通过独立受控渠道取得最新 SHA-256，旧包即使签名有效也不能通过当前校验。恢复包和摘要分别保管。指纹只接受由已知权威环境生成并由责任人核对的值。
- 恢复先比较外置摘要、签名、模式、时间和来源覆盖。旧库中的来源记录与最新状态、权限 epoch 或许可摘要有差异时保守隔离，推进权限 epoch 并使用现有媒体清理 outbox。任何缺失的旧库来源覆盖会拒绝重放。此次恢复只处理本机合成来源。
- 无法与最新记录比对的旧会话、API key、未消费认证令牌与分享被撤销或消费，旧匿名发布被移除；符合条件的已存在权利保持可读。该步骤与账户标记、来源隔离同事务提交，然后运行现有账户分批清理。独立验证仍需核对密码、MFA、管理员授权、真实来源副本和备份后付款事实，最终开读需按实际环境签收。

离线验证用实际 PG16 备份恢复演练：先对隔离测试库作 `pg_dump --format=custom`，再提交合成账户删除，从新库导出删除清单。恢复旧快照至另外一个专用测试数据库，保持API关闭，使用同一 `LOCAL_STATE_ROOT` 的认证密钥验签重放。禁止拿生产库和真实个人数据跑此命令。

```sh
npm run privacy:recovery -- export .local/recovery-checkpoint.json
# 从最新检查点的独立受控登记取得 RECOVERY_APPROVED_SHA256。
# 把 DATABASE_URL 明确指向已恢复、未接入流量的专用测试库。
PRIVACY_RESTORE_ISOLATED=true PRIVACY_RECOVERY_MANIFEST_SHA256="$RECOVERY_APPROVED_SHA256" \
  npm run privacy:recovery -- replay .local/recovery-checkpoint.json
```

导出文件用 0600 独占创建，输出摘要供独立登记。脚本拒绝符号链接、松权限、旧包、错误签名、来源缺口和未来记录，并限制大小及条数。早期账户清单保留作历史证据，新 CLI 重放需 v2 恢复包。检查恢复后旧会话、key、分享、匿名发布及被撤权的成交和主图是否拒读，并逐条核对原始额度流水。清理达上限时保持隔离，重试完成后再复核。生产需有外置防篡改、可靠的最新标记来源和恢复验证。
