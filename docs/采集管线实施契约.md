# 自研采集与证据管线实施契约

2026-11-16；用户要求优先贯通采集系统并按整包推进。本包覆盖TASK-012/013/014/015/016的持久化离线工程，继承ADR-13与采集稳定性专项，禁止真实eBay请求或第三方代抓取。状态只在任务台账；该契约不授予来源许可。

## 1. 本包交付及真实入口边界

形成 `enqueue → lease → 原子预算预留 → 合成响应 → classify/parse → PG观察/事件/媒体状态/检查点 → 完整水位 → 共享统计` 的可执行离线链。使用专用PG16数据库、内存fixture transport、本地私有媒体对象目录。新runner只接受offline_fixture来源和明确synthetic envelope，不能因数据库写active/clearance记录就开启网络。现有approved HTTP/browser仍只有纯预检，不开放真实派发；真实DOM/字段证据及访问准入到位后再做adapter实测，不编造eBay选择器。

## 2. 并发与预算规则

队列按来源+query hash+显式run key幂等，固定as_of；同run key不同输入拒绝，不把不同日期查询混合。来源行锁串行协调准入/熔断/预算；领取作业生成随机lease token、递增attempt，过期lease可在原检查点接管，旧token不能提交。并发上限/每分钟请求数、每任务页数/请求数/字节、UTC日jobs/pages/bytes预算由PG事实源约束。配置变化和epoch变化禁止继续旧快照。

每次预留一个请求、一个页额度及最大响应字节；分钟计数在预留时消费，不因已派发失败释放，避免高并发重试突破限速。响应/失败结算把实际字节与页从reserved移到used；进程崩溃遗留reservation在接管时按最大预留量保守消耗，不重发到无限预算；超过每日预算当天不恢复。图片请求独立预算预留，图像字节也计入源/任务总预算，不伪装免费网络成本。

所有租约、重试、预算日、许可/熔断检查默认DB时钟；离线测试显式固定时钟，不冒充真实连续运行。429遵Retry-After后排队，5xx有界重试；401/403/登录墙/挑战持久熔断、先阻断后续派发，不能换账号/出口。每job最多3次失败尝试（工程基线）；正常429/本地速率等待不消耗失败次数，lease_count单独记录，仍受总deadline/请求/字节预算约束，取消/超期不推进水位。

## 3. 证据、事件身份与恢复

合成页包含schema/synthetic/source/query/cursor/next/as_of/records，解析先验证所有绑定、字节/条数上限及字段资格，正常空结果须明确empty marker；结构错误隔离，不作成功空页。未知事件身份保留uncertain观测，不虚构独立成交。source_event_key与listing/事实hash冲突时停止/隔离，不覆盖旧事实。

每页提交单事务写source_observation、listing、sale_event及对应observation evidence、合成raw证据/规范候选、媒体待处理状态、outbox和cursor。重复观察只补证据，不新增成交。同一事件可有多个observations，图片须组合外键关联其中实际对应的event/listing/source/observation证据，不能只绑定首个观察。

只有完整终页提交才写本次run完整水位；data_as_of取本次页as_of最小值，partial不推进完整水位。循环cursor/重复页/页数预算/中途异常均明确partial/failed；重启沿已提交检查点恢复。不把抓取时间当成交时间。

## 4. 商品主图与私有对象

页主图候选必须附同listing的primary角色，合成图像transport不进行外网；正常无图与失败/未许可分开。经过现有media解码/去EXIF/WebP规范化后写私有对象，再用DB事务复核当前source epoch/lease及证据关联后标available。中途撤销拒绝提交；孤儿文件可清理，不反向公开。原始URL不回API，生产URL仍应用加密保存。

本包提供worker内部受权读取/撤销拒读与删除；公开owner媒体HTTP路由仍属TASK-028/账户查询服务，不用内部worker方法替代owner授权。对象key只由服务端UUID/hash产生，目录/文件权限最小化，内容hash校验，禁止任意路径/上游重定向。

## 5. 完成与证据

验证PG16空库/上一版升级、并发争抢/预算不超、幂等、租约过期接管/旧token拒绝、撤销/403后重开进程仍停止、429等待、重复页/身份冲突/事务失败不推进、完整黄金121/64/58贯通与商品主图文件/证据/缺图/撤销。共享统计/计费规则不复制。命令/源码hash/测试模式/缺项回填台账；未完成线上14天、生产型7天和独立复核不签G1。

## 6. 本包实际实现与已知前置

实际追加0005迁移复用原collector_jobs/collector_circuits，不建立第二套任务或熔断真相；新增dispatch/rate window/page/evidence/watermark五表。旧库49表升级为54表，既有事件/主图证据先回填再收紧组合外键，旧列与原数据保留。collector运行版本offline-pg-1.0.0、synthetic parser 1.0.0，source approval仍draft/NOT_CLEARED。

同一source行锁串行协调租约/预算/取消/停止/撤销。采集熔断停止新请求，但不撤销仍有效的既有缓存；真正撤销在单事务内更新source status/epoch、停止任务、保守结算未确认预算并写媒体清理outbox，随后读立即拒绝，清理可重放。bytes_in记录已结算响应，bytes_unconfirmed独立记录崩溃预留的未知字节上限，不把未知量伪装成实测网络流量。

文件发布与图片关联放在同一source/job锁内，网络响应和解码在锁外完成；发布前后检查租约，失败SAVEPOINT回滚并清理无引用文件。撤销清理同时枚举来源命名空间的生成对象/暂存文件，覆盖崩溃孤儿。原始媒体URL仅出现在受限合成page证据，不进入用户DTO；生产URL加密/来源字段权利仍需实际adapter接入验证。过期图片读取立即拒绝；本包已实现过期引用/共享对象保护/老孤儿扫描，生产对象存储耐久/恢复与owner媒体HTTP尚须后续实现/验收，不能以私有本地目录代替生产S3/R2部署。

主图唯一键与查找均使用event/listing/observation/role，支持同listing同页多笔独立成交；重复事件多次观察只加evidence。未知候选按单条获准record证据指纹去重，排除分页游标/行位置/图片；它仅是uncertain候选，不证明实际成交。快照读取按本run的已提交页序为每event取最新规范候选，防止补seller/成色等元数据产生假价格冲突；不同成交事实仍拒绝覆盖。

下一真实前置：来源逐字段访问/保存/统计/主图展示及再分发权、获准HTML/原始响应样本与结构签名、真实entrypoint/method/rate参数、实际自研HTTP/browser adapter、独立出口/资源/部署审计、14天获准验证和7天生产型稳定观察。当前fixture-only runner明确拒绝approved_http/browser，因此没有任何离线数据库行可以解锁网络。

## 7. 留存维护与运行限制

`runOne`每次领取前执行该来源维护；也可独立运行`npm run collector:maintain`。维护在源行锁内使过期图片引用失效，仍有有效引用的同hash共享对象保留；明确synthetic存储期限（helper为1天）之外的未引用生成对象/暂存文件按mtime清理。撤销源即便清理事件已处理仍可重复扫描，防止遗漏历史孤儿。DB/注入时钟无效直接拒读/停止清理，不延长可见期。

生产部署时必须配置独立维护调度、进程监管、备份与恢复，服务器尚未购买/部署，不把CLI存在当作已运行的周期任务。两个CLI按PG驱动最终解析目标检查本地/受控socket，拒绝query-host、PGHOST或多主机绕过；只处理offline_fixture，不连真实来源。

源字段45项的真实可得性仍全未核验。本文canonical synthetic page parser不是eBay HTML/浏览器生产parser；真实结构选择器/页面变更回归需要获准样本，不能用合成数据和45个字段名就报告供数稳定。

## 9. 结构漂移与冲突隔离包契约

继续TASK-014/015/016：200但非约定内容类型、无效JSON/字段/绑定、分页循环、既有事件事实冲突，不再只失败当前job后允许其他job继续尝试；保存有界隔离摘要并在同事务打开来源采集熔断、停止排队任务。保留已提交partial页，不写完整水位。仅保存原始响应hash、大小、dispatch/run/parser/cursor/原因及可确定的受争议事件ID，不保存失败页原文、标题、URL、异常消息或凭证。

继续TASK-016/017的离线部分。增加单周期受控启动器，只启动仓库自有fixture worker、不接受任意命令；限制V8 heap、单周期运行时长和优雅退出宽限，超时先SIGTERM再SIGKILL，转发外部终止并等待实际子进程退出。子进程仅接收必要本地DB/目录及OS基础环境，不继承NODE_OPTIONS/NODE_PATH或支付、会话、客户API密钥。启动器不重试、不重开来源、不修改账务/检查点，不将周期退出0当完整供数成功。

## 13. 冻结刷新计划与可核查调度分母

本包只实现offline_fixture的PG运行计划，不替代获准真实入口。每个计划固定source/config、collection query hash、collector/parser/profile、完整配置与权限epoch快照、start、间隔和允许延迟；正常变更通过退休旧计划和创建新ID，历史发生项不可改写为新时间。每source/query同一时刻至多一个未退休计划。

planner按冻结start/interval重建到当前时钟的每个发生项，超允许延迟记missed并保留；有限批次推进next_due，不跳过未记录的周期。退休为[start,retired_at)，退休前遗漏周期仍须补记。执行率的分母按冻结计划数学计算（含尚未来得及写发生表的漏调度），不能仅数worker实际拿到的消息；没有计划仍null。

发生项先领PG lease并固定第一次派发as_of，再调用共用CollectorStore.enqueue，固定runKey与预期来源/配置签名；崩溃后重放相同输入，不新增job/预算。到期、阻断与被取消的计划记录原因，不绕过source许可、circuit、共享Retry-After和日预算。任务创建不等于采集执行，执行分子要求collector_jobs.started_at实际存在。

完整配置签名包含实际source身份/许可ID/epoch/entrypoint及collector_config的入口、方法、速率、并发、页/字节上限、启用、版本和审批引用，不只依赖updated_at。未经更新updated_at的参数变化同样失配；运行版本升级不能静默复用旧配置审批。

退休边界使用声明时钟的下一毫秒，保留同毫秒已到期/已生成的周期；数据库拒绝让退休时间排除任何已生成历史发生项。发生项终态和计划固定参数不可改写/删除。派发lease同时绑定runKey、TTL、query/source/config/hash及collector/parser/profile，不能用一个token创建不同作业。

`npm run collector:refresh -- --action=create --source=UUID --config=UUID --query='q=Game+Boy+Color' --key=UNIQUE_ASCII_KEY_16_PLUS --interval=3600 --lag=300`创建冻结计划；默认start为DB当前时钟（显式--clock仅模拟）。有HTML profile时创建/周期派发必须传相同--profile绝对路径。`--action=cycle --source=UUID`以有界批次补发生项并入队，重复调用幂等，不读取页面、不抓图；原独立worker仍负责执行。`--action=retire --source=UUID --plan=UUID`停止未来派发，保留历史。CLI拒绝与action不符的参数，不自动换源/版本/配置。

报告scheduleExecutionRate=实际started_at存在的计划作业/窗口内冻结应发生数；scheduleOnTimeRate另外要求started_at不晚于该周期deadline（包含边界）。创建job仅queued不算执行成功。分母含未生成、missed、blocked，未来start分母0时ratio=null。一次cycle最多补1000个slot和尝试派发100个job，可重复执行追赶，不能把cycle退出0视为全部完成。当前UTC日预算必须事先存在，尚无自动滚动审批预算，缺少当日预算fail closed；下一整包另行补齐，不能借用上一日额度。

## 16. 主图目录归属与删除确认

一个本机离线source关联一个媒体根，通过解析后的目录位置与文件系统身份绑定。首次Worker主图发布在文件写入前提交绑定，进程在写入后崩溃也能找到待处理命名空间。绑定一旦建立不能隐式更换。旧来源在每条已存对象引用可按hash从同一根读回时确认为该根，并在删除前独立持久确认；无法证明时保留待清理，不抹掉链接或确认outbox。没有存储引用且没有图片派发记录时可确认无需清理已登记主图。旧来源曾派发却只有未绑定孤儿时，可移除本地孤儿，未核实其他旧目录前保留待确认。

撤权清理和确认在同一来源行锁事务中操作，只有对应目录可确认。媒体撤销以source权利即时拒读，删除失败则待重跑。权限仍有效的主图如果共享内容对象，过期清理不删除它们。服务关闭或熔断不等于撤权。CLI优先使用显式MEDIA_ROOT，其次本机演示目录下collector-media，输出仍有多少待清理/归属待核验。

页面Worker只执行必要的来源准入检查，实际删除由独立的 `npm run collector:maintain` 运行。每个使用的MEDIA_ROOT需各自运行维护；单源磁盘失败保留待办，CLI继续其他来源并用非零退出报告失败。临时重建或移动目录时不能让该来源通过身份校验，须恢复原目录或走受控迁移；不要改写绑定。

## 18. 单来源离线自动运行

`collector:supervise` 从明确选定的本机合成来源读取实际待办，只认指定目录下现有的 `collector-fixture-<job_id>.json` 或 `collector-html-fixture-<job_id>.json`。文件名、响应包的 job、PG 中的来源/查询/时点、冻结的响应包摘要必须匹配。重名和符号链接不进入派发，旧 CLI 仍可直接提供一个合规的文件。每类每轮最多按 PG 队列检查 64 个到期作业及其对应文件，历史文件不参与候选查找。每轮最多执行四个页面作业和四个媒体父作业，子进程沿用有界启动器、lease、预算及获取前的许可守卫。

`--watch=true` 以数据库时钟检查页面和主图重试的到期，正常停止后可重启续跑。缺包保留在 `queues.*.artifactUnavailable`，出错或未领取的子进程短暂让开队列并显示 `deferred`。该让步只在当前进程有效。状态有来源停用、熔断、退避和预算失效，报告包含真实领取、子进程退出和补采结果。一个来源通过独立 PG 会话锁限制自动运行器实例。自动运行的本机状态文件按作业和类型覆盖写到单独目录，实际事实仍由 PG 保存。来源撤权及目录归属仍由现有独立维护逻辑检查。运行器首次执行维护，持续运行时按分钟重查，实际清理仍须以 `cleanupProcessed`、主图状态及对象读取结果为准。

离线响应包由入站入口先写入待发布目录，再在 PG 绑定摘要并原子发布完整文件。没有匹配响应包的新刷新作业继续等待。真实平台适配、授予许可、连续验证、生产部署，以及告警送达由对应 TASK 验收。`ready` 只表示当前运行前置允许继续尝试，队列和子进程结果才说明实际执行情况。

监听模式遇到已分类的 PG 连接中断，以 1–10 秒退避重新验证来源并取得独立会话锁。旧会话失锁时先停止正在运行的子进程，确认退出才尝试恢复。若另一实例已持锁，退出并报告 `already_supervised`。子进程通过 IPC 感知父进程非正常退出，停止工作并有两秒退出期限。分页、主图和预算仍由既有租约及持久检查点恢复。连接异常和恢复分别用明确日志标识，程序错误保留失败状态。

已有冻结计划可用 `collector:supervise -- --source=UUID --spool=目录 --watch=true --refresh=true` 自动推进。每轮最多补登记 200 个时段、关闭 100 个已到截止且无已入队作业的旧时段，并尝试派发 8 个作业。来源尚未就绪时仍可登记和关闭旧时段。已提交的作业保留原恢复路径，最终执行仍需已绑定的合成响应包。默认仅派发 JSON 计划。HTML 计划传 `--refresh-profile=/绝对路径/profile.json`，只处理摘要匹配的作业。同时维护多个格式可保留手动周期入口。当前轮统计在 `scheduled` 中显示登记、是否还有待登记、过期关闭、入队、恢复及阻断。未开启 `--refresh=true` 时沿用原监听行为。

## 19. 逐日采集执行证据

`npm run collector:report -- --source=UUID --daily-days=14` 返回最近 14 个完整 UTC 自然日，`7` 用于同口径短窗。区间为 `[daily.from, daily.until)`，截至当日 UTC 零点。没有数据的日也输出，从冻结计划自动还原未生成的发生项。单项作业按计划日计入实际启动、准时启动、截至检查时点的完成和失败，页面、主图请求量按实际发起日入账。跨午夜完成的作业归原计划日，请求归新日。

日表是同一数据库快照内的内部聚合，可选 `--clock` 模拟固定时钟。`planned=0` 表示本来源当日无冻结任务。生成日表只查合成来源的运行记录，CLI 仍按原机制保存报告快照。页面原文、照片和账号均不在日表输入中。外部访问、真实费率、实际 eBay 质量和正式稳定性结论仍需对应证据。

`media.primaryImageCoverage` 按报告区间内的成交观察计数。页面上每个已保存的成交观察都进入分母，缺图和无主图元数据的记录分别记为 `missing`、`untracked`，同一图像对象可关联多条观察。分子仅计入当前权利、保留期、权限版本及隔离状态允许读取的主图引用。零观察时比例为 `null`。对象实际读取和字节完整性仍由 `--check-media` 抽检并按去重对象另报。

## 20. 离线响应包入站和中断恢复

已入队的定时合成作业可用 `npm run collector:handoff -- --source=UUID` 查询。结果包含冻结查询摘要、计划和作业 ID、时间窗、解析配置与已绑定包摘要。使用 `--limit=100` 和返回的 `nextAfter` 查看下一批。入口只列当前许可版本下仍存活的本机合成作业。

JSON 作业可用 `npm run collector:handoff -- --action=package --source=UUID --job=UUID --template=/path/to/template.json --spool=.local`。模板 schema 为 `soldbench.collector-json-responses.v1`，要求 `synthetic:true`、`pages` 和可选 `images`。页写 `cursor`、`nextCursor`、`records`（复用合成页记录，允许省略候选 `sourceId`）。页链从 `start` 开始，最后一页 `nextCursor:null`。主图使用 `{url,contentType,bytesBase64}` 提供本地合成图像数据，必须与记录中的对应主图候选一致。工具绑定数据库内原查询和日期，复用入站与解析校验。HTML 作业继续用具有原配置及绑定的原始合成响应包走入站。

`npm run collector:intake -- --source=UUID --spool=.local --fixture=/absolute/path/to/artifact.json` 接受待执行或需补采的现有本机合成作业。输入须匹配 PG 中的来源、作业、查询、时间、解析配置及此前提交的页面。入口接受最多 16 MiB 的常规文件，拒绝符号链接，保留内容摘要。JSON 与合成 HTML 演示共用同一入口。

待发布文件写入 `collector-incoming/{sourceId}/{jobId}.{sha256}.json`，同步文件再同步目录。写入完整后才绑定 PG 摘要并发布给 Worker。相同摘要重试幂等，冲突不覆盖已绑定或已发布证据。监听模式每轮最多恢复四个待发布文件，恢复结果见 `intake.published`、`intake.deferred` 和 `intake.status`。中断发生在落盘以后时，下一轮可完成绑定和发布。出错文件继续留在待发布区供核查，其他作业仍可执行。每一页和主图照常通过原派发守卫、预算和租约判断。

## 21. 缺包和目录故障期间的队列收口

监督者每轮先在 PG 关闭达到截止时间、用尽重试次数或父作业已终止的对应待办。每轮最多 50 个页面作业及 50 个主图作业。维护 CLI 也执行相同操作。仍持有有效租约的工作保留；回收失租任务时把未知派发按原 UTC 预算日一次结算。缺少响应包时零新派发，仍能清理过期待办。主图重试关闭保留已有成交快照和可用主图。

监听模式遇到暂时缺少响应目录、权限或打开文件限制时记录 `spool_unavailable`。连接、权利、预算和租约检查继续进行，目录恢复后同一进程继续。源停用和熔断另有各自状态，目录恢复不会改变来源停用或熔断。

## 22. 大量历史文件和缺包待办

监督者先从 PG 读取页面和媒体两类的到期总量，再按队列位置逐批验证响应包。`due` 为当轮到期总量，`scanned` 为检查的作业数。`artifactUnavailable`、`withArtifact` 和 `deferred` 仅统计检查过的作业，`uninspected` 保留尚未检查的数量。单轮执行读取第一批，持续监听时记住两类位置并循环检查，越过缺包作业，仍会回到原队列检查后来到达的文件。目录恢复后从原检查位置继续。
