# 发布、回滚与撤权恢复手册

2026-11-18，适用 TASK-011/012/035/038/039/040/041/042/043、RB-1 至 RB-7。当前代码 808b9875 的执行环境为本机合成数据；生产环境、域名服务、真实收款和五门签署尚待提供。以下“预发布”步骤是接入前的操作及验收设计。实际域名、托管平台和响应人员以届时经签收的部署记录为准。

## 1. 值班交接和停止条件

交接记录包含事件/变更编号、环境、UTC 起止时间、服务/来源/clearance、当前 epoch、软件 SHA 与迁移编号、受影响读写路径、是否影响资金、值班主责、业务/权利负责人、操作人、复核者及受控证据引用。原始密钥、访问令牌、客户正文与支付凭据留在各受控系统。

| 触发 | 首个动作 | 谁决定恢复 |
|---|---|---|
| 权利撤回、到期、疑似越权分发 | 撤权或隔离受影响来源的所有分发面，停止采集；记录拒读生效时点、受影响对象和工单。暂不能限定范围时扩大隔离直至定位 | 权利负责人确认范围/新许可，值班人抽验后复核 |
| 技术断源、挑战、401/403 | 暂停新采集，保持仅在当前权利允许时读取合法历史。记录水位和预算；挑战/登录墙须先由负责人处理 | 运维和值班权利负责人确认恢复条件 |
| 余额不平、重复权益、错收或资金差异 | 停受影响的新收费操作；保存原始收款事实、渠道及账本引用。保持无风险历史读取；按支付规格对账 | 账务负责人逐笔解释差异，非实现者核对 |
| DB 目标不明、备份密钥/最新撤权记录不可核验 | 在建池、迁移或开放任何读者前停止该操作，隔离恢复副本 | 资源所有者核对实例身份和外置水位 |
| worker 停止、队列持续变旧 | 停止接受无法按预算完成的新任务，保留已交付查询、账户、账单可读；告警记录到人时间 | 运维确认队列恢复与无重复收费 |

## 2. 发布预检和回退分支

1. 锁定上一可运行产物与待发布 SHA、依赖锁、迁移前后版本、配置摘要、权限和计费版本。记录原镜像/构建的受控引用，测能否在新 schema 上运行旧读者。DNS/TLS、API 目标、双语事务邮件和真实渠道凭证分别按批准环境验证。
2. 按下方 S1 入口表确认 PG 目标和迁移权，再启动程序。当前只在经过确认的临时 PG16 运行本机集成。发布使用独立迁移角色及最小权限应用角色。
3. 在隔离库恢复备份并执行追加迁移，核文件 hash、FK/唯一约束、owner 分区、余额/流水、授权与权限 epoch。迁移 0003/0004 涉及源 URL 加密时按工程规格的分步核验执行。已有迁移不可改写。未能对账、数据解密或旧读者兼容测试失败时终止切换。
4. 预发布分别监督 API、query worker、Collector。先测健康，再从被授权的客户入口做“查到结果—领取—复取—查账”，测只读服务、队列最老未处理时间、最近成功处理、媒体清理失败、支付差异与通知送达。`/health` 表示进程响应，`/ready` 探测数据库并报告查询 worker 和排队延迟。监控需读取响应字段并按预发布实际拓扑验收（S4）。
5. 切换期间保留变更前后的延迟/错误、权利拒读、扣费与积压对照。原稿 §13 的 P0 立即隔离，P1 按原 SLA 通知，冻结扩大范围。如新代码回归且旧读者兼容当前 schema，回切上一可运行构建并复核读写/账务；遇损坏或不兼容，先限流/隔离，选择追加修复迁移或执行第 3 节的隔离恢复。业务回退不得回退已提交支付、退款、删除或许可撤销。
6. 授权负责人附业务验收、当前来源有效性、阶段签收及 AT-054 真交易证据后决定是否开放真实流量；离线允许继续开发。每次对外切换记录环境、时间、操作人、负责人、恢复/停留结论和遗留限制。

### S1 离线数据库目标、开机与迁移

| 入口 | 目标来源与当前启动行为 | 建池前核验 |
|---|---|---|
| API，`apps/api/src/server.ts` | `loadConfig` 从 DATABASE_URL 取有效 URL，缺失即停。入口执行 migrate 后启动监听 | 808b987 仅 PAYMENT_FIXTURES 时检查本机目标，普通离线路径待加守卫 |
| 查询 worker，`scripts/query-worker.mjs` | 配置 DATABASE_URL 优先，回退本机 socket。建池后先 migrate，之后进入工作循环 | 已在建池前校验本机 URL 与允许的 socket |
| 迁移 CLI，`scripts/migrate.mjs` | DATABASE_URL 优先，没有时回退本机 socket。显式运行立即执行 migrate | 808b987 此入口无同等目标校验，待接入 |

离线目标顺序为先确认独立 PG16 实例和允许 socket，再用受控迁移角色升级，随后启动 API 和 query worker，核 schema 和 readiness 后才能接受测试流量。现有 API 与 worker 均自动执行迁移，迁移隔离的发布方案须按工程任务实施。S1 关闭检查用替身连接器验证错误目的地在任何建池或迁移动作前被拒；另用独立空库和上一版测试库跑合法升级与启动。配置来源、目标标识和退出码脱敏留档。

## 3. 恢复旧库、对象与撤权记录（S3）

已有可执行的本机路径使用 PG16 隔离备份、v2 恢复包、同一受控密钥和从权威库单独登记的最新摘要，详见[账户删除与恢复保护](账户删除与恢复保护实施契约.md)。它可拒绝仍有有效签名的旧包，重放合成来源的隔离、账户删除与凭据撤销。外部最新性发布、生产对象副本清理及跨机恢复尚未验收。

| 顺序 | 预发布值班操作 | 允许进入下一步的证据 |
|---|---|---|
| 1 隔离 | 在新实例/命名空间恢复，关闭所有公开及私有读者、分享、CDN 回源、worker、定时任务、付款与发信；保留原库和金库 | 实例身份、备份 ID、对象版本与截止时点，以及外部读流量为零的证据 |
| 2 选定恢复点 | 从独立保管处取最新已签账户删除与凭据撤销序列、来源/字段撤销序列及 epoch、水位、适用商户和密钥版本。与独立最新检查点比较；账本另取备份点后付款/退款清单 | 各清单源、环境、签名、序列无缺口、覆盖至切换时点；旧清单即使签名有效也阻断重开。本机 CLI 核对独立提供的摘要，生产外置签发和保管机制待验 |
| 3 重放 | 对隔离库重放账户删除及独立撤销/轮换，再逐来源/字段撤权、禁旧分享和结果，用当前 epoch 清理媒体文件、缓存、分发/SEO 副本，重建有权索引。新进撤销持续收取到切流前并再次核对 | 账户批次结束、无未解撤权缺口；跨源快照整体拒读或由新的合法子集另产快照。缺任一权限依据时相应链路继续拒读 |
| 4 对账 | 比较恢复前后钱包与不可变流水、charge 与结果、已确认支付/grant、已退款/争议、未领取 ready。旧备份之后的渠道事实按原业务键核对与恢复；账户删除不得复活已取消授权 | 全部金额分币核对；待结算差异有负责人和确定边界。无法解释的差异继续封锁受影响收费交易 |
| 5 读链抽验 | 用已删账户旧会话/key、活动账户单独撤销或已轮换的旧 key、已撤会话、旧分享、匿名快照、媒体、可重算输入、详情/导出、MCP 和旧缓存读取；再用允许账户读合法历史。将拒读及清理回执分别记录 | 已撤数据全部拒读（含撤销后到清理完成期间），允许数据可读，旧主图无旁路，快照恢复不增 charge |
| 6 逐步开放 | 先开放已证明可用且合法的读链；后台先受控小范围重放，后视门禁恢复新查询/收费/采集。保留原实例供隔离复核 | RPO 用事故点减去可恢复的最后已核实数据点；RTO 用中断到经核验恢复服务的时间。分别记录只读和完整恢复时点，按目标 RPO≤24h、RTO≤4h 与实际负载签收 |

恢复验收至少留一组负例：提供较旧但签名有效的账户清单、缺一个撤权来源或缺密钥，读者必须持续隔离。用合成的备份后交易和撤权证明零重复 grant、零恢复越权。当前仓库本机历史证据见[账户演练](../step0/evidence/account-privacy-20261118/validation.json)和[断源演练](../step0/evidence/outage-readiness-20261118/validation.json)。

## 4. 故障与容量演练（S4、D4）

本机可复验下列已有断言。测试启动独立临时 PG16，以 Node 22 和仓库规定依赖运行；应记录命令、实际退出码与版本。源权利、现网拓扑、银行结算和 RPO/RTO 签收各自取证。

```sh
npm run build
node scripts/test.mjs tests/database.test.mjs tests/privacy.test.mjs tests/operations.test.mjs tests/readiness.test.mjs tests/payments.test.mjs
```

- **断源**。依次注入 0/24/48/72 小时及边界后 1ms。fresh ≤24h、stale ≤72h 为候选值，陈旧结果仅显式接受并免费，超窗不能作当前价，撤权即时拒读。停 query worker/Collector、缓存冷启动和恢复分别测试；保持账户/账单可读，核期间重复事件与 charge 增量为零。对恢复后的新水位单测不复用旧撤权结果。预发布再实际隔离 Collector 与 Redis，记录告警、切换与恢复。
- **本机查询 worker 隔离**。`scripts/dev.mjs` 在 worker 退出时保留 API，按 1、2、4 秒最多重启三次，稳定运行满一分钟重置预算。日志事件 `query_worker_exited` 的 `restart_ms=null` 表示等待人工处理。可独立用 `npm run query:worker -- --watch` 恢复，沿用同一已验证本机数据库、秘钥和媒体目录。`/ready` 的 `query_worker` 为 `recent`、`stale` 或 `unobserved`，超过 30 秒无处理循环心跳为 `stale`。可运行的查询已等待至少 15 秒时 `query_queue=delayed`。数据库正常时上述降级仍返回 200，已有获权读取继续可用；监控不能只看 HTTP 状态。数据库不可用时 `/ready` 为 503，`/health` 仍仅表示 API 进程响应。部署前还需在真实拓扑验证监督者重启上限、阻塞检测、告警到人及数据库断开恢复。
- **容量**。历史 p95 31.09ms 来自本机 150 次公开分享读取、50 并发。预发布按 DEC-11 的 2vCPU/4GB API 和 DB、独立 Collector，固定带权限的同一候选规模，测 limit=1/50/200、有图/缺图、冷热快照、单/多 owner、并发 50 的私有读取及带图领取。为各场景记录实际 SQL 条数、租约/锁等待、PG/应用 CPU 与 RSS、对象读取/字节、队列时延、HTTP p50/p95/p99、失败率和每次成功交付总成本。顺带核各 limit 同统计、最多 1 credit、撤权后无返回。候选集或机器不同需分栏；收到主路径证据后再决定批读/批写。核 AT-041 缓存 p95≤800ms、允许实时≤15s 否则 202，另测移动 4G LCP≤2.5s。
- **交班签收**。把场景版本、样本、观测区间、时钟、真实耗时、失败和恢复动作与资源所有者关联；缺生产数据标 NOT VERIFIED。工程负责人对接 AT-039/041/042/046/047/048/049，非实现者按 AT-053 复核，创始人处理实际发布门。

台账 §80 的本机容量复验使用两个合成账户各 25 并发，保留每 owner 的原限流。`tests/readiness.test.mjs` 输出 1、50、200 条私有结果的事务 SQL、主图 SQL、响应字节、p50、p95 和 p99。主图许可撤销时主图查询为 0。生产拓扑仍须验证真实网络、容量和成本。

数据库运行中断时，查询 Worker 保留连接故障前的作业租约，进入有限频率的重连等待。API `/ready` 会返回 503 和建议重试秒数，`/health` 继续报告 API 进程状态。数据库恢复后先核对就绪及新的工作循环心跳，再用原幂等键核对未明确完成的领取、支付与其他写入。事务层不会替操作者重发写入。台账 §82 记录当前注入测试与实际停机验收的状态。

支持受理、投诉和撤权分派见[运营契约](运营后端实施契约.md)；原渠道现金/本地权益/银行出款对账见[支付规格](Stripe与PayPal接入规格.md)。

Q06 的本机恢复包保留活动账户仍获准的 key，并用当前权利视图注销被单独撤销的旧 key、旧会话和已用认证令牌。生产撤销/轮换序列由安全和运维签收。缺可信记录时保持受影响凭据关闭，按换发流程恢复有权客户端。
