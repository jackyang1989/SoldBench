# 查询账本与交付实施契约

2026-11-17；TASK-025/026/027/028离线工程，继承ADR-11/12/13、原稿§7/9/11和AT-019…030/040/056/075。所有入口复用相同PG领域服务，不执行真实采集、支付或发信。用户/结果/资金变化留审计，不改已应用迁移。

## 1. 身份与快照

owner来自已验证session/key，写操作在用户锁内复查当前身份/状态/scopes/撤销，不能信任请求body中的owner。Cookie耗费查询与写操作要求Origin/CSRF；API Key在服务端读取，不进入浏览器示例。10分钟owner复用从query.created_at算，不因轮询延长；query hash仍包含limit/allow_stale。底层collection hash单独版本化，去除只影响交付的limit/allow_stale；保留q/站点/类目/属性/窗口/口径/价格及format，不能拿一个夹具回答任意关键词。

只有相同collection hash、已完整提交watermark的offline_fixture job可以成为本包数据输入；无匹配快照且真实采集关闭时503，不建立永远pending的任务。查询固定来源job、计算as_of与数据水位，缓存统计沿该输入截止点计算，不随复取时间漂移。复制完整候选/证据关联到私有query快照，不按返回limit计算。源码版本、权利epoch或事件争议不匹配时拒绝复用/交付。

## 2. 余额与流水

邮箱核验锚点按UTC月周年发100credit，月底截断但不漂移原锚点；只发当前期，不补发已错过的期。每user/类别/provider/period或payment唯一grant，不把policy版本加入唯一身份。订阅/有限promo最早到期优先，同到期subscription优先，最后purchased；过期先expire流水，再消费。所有金额/credit为整数，钱包+流水同事务、流水不可改写。

每query唯一charge最多1credit；有价样本>=8且fresh/当前权利有效才可结算。低样本、stale显式允许、排队/失败/轮询/重复复取不扣费；claim幂等成功只记一次，但每次读仍复查当前权限。余额不足402保留ready，换新幂等键充值后可领取，失败不占成功幂等记录。

credit refund每charge一次：有效原桶返原；失效桶返30天promo，追加反向流水不修改原消费。现金退款仅处理已经由内部可信支付记录确认的全额退款，先撤原grant未用余额、实际已消费未credit退款部分写credit_recoveries，暂停新收费，不使wallet负数；不删除已购结果。当前仅合成支付记录测试，没有真实供应商连接/用户任意grant入口。

## 3. 异步与交付

创建query/job/outbox原子，完成计算仅ready不扣费；独立worker用lease/CAS与有界重试，取消/过期/旧lease不能迟到发布。GET job只给状态和领取URL；POST claim同事务检查当前owner、来源、retention、新鲜度、样本、版本、余额并发布。未领取付费GET result为409；已交付GET免费，并区分本次0与历史总扣费。24h未领取到期，已completed job不倒退；已购历史仅在当前权利和保留期允许时免费读取。

完整计算输入、JSON/CSV与主图读取仅限已可读取的本人快照；图片必须属于该快照的event/listing/observation且当前epoch/有效期一致，不回上游URL。CSV对可执行公式前缀转义，导出不新查/不加收费。翻译/展示排序不改变统计、query身份或费用。

锁序为user→query/job→source（稳定ID顺序）→wallet→账本/outbox。source撤销不等异步删除，读立即拒绝；采集进程停止不影响有权快照。Redis不作为唯一事实源，本包队列与复用从PG恢复；线上Redis/BullMQ/对象存储与阶段门仍单独验收。

## 5. 实施补充（2026-11-17）

- 运行billing1.1.0、collector offline-pg-1.4.0。统计数值规则不变，worker使用同一次资格判定生成完整输入；合成retention显式1–30天，默认1天，不忽略保留期来展示stale。响应标记为synthetic_fixture并带合成数据警告，不返回虚构的来源核验结论。
- 已完成结果按创建时间10分钟复用；同参数仍在途则复用现有job直到终态或24h到期，避免活动唯一索引冲突。取消、到期与租约恢复不能迟到发布。
- Free升级、降级和付费速率需要对应已确认付款、subscription grant与相同周期的钱包；未付款checkout不能重锚。Free 30/min，付费按当前plan限制，owner跨key共享PG计数，429含Retry-After。
- 支付grant以实际payment_id作业务身份，通知事件ID不是付款身份；数据库另有user/kind/payment唯一索引，policy变更不重复发放。
- credit退款仍是内部admin角色与reason审计命令，未暴露客户接口。操作者确认补偿后，递归跟踪原付款的补偿钱包及后续消费；确认现金退款撤回所有未用补偿。仅仍实际收费的后代计入recoveries；操作者补偿使未偿部分为0时对账resolved，不豁免仍存在的债务。
- 不兼容的计算版本拒绝交付并允许重新计算；响应使用实际冻结版本。JSON attributes与attr_*共用现行类目allowlist。JobAccepted可报告completed复用，JobView.version供取消CAS使用。query/ledger游标绑定owner、资源类型和完整微秒时间。
- 首次auth secret通过完整0600临时文件、fsync、原子hardlink发布，避免API和worker并发首启读到半文件。
- 本包不包含匿名、公开分享、完整详情/诊断HTTP、导出下载、请求日志页面、支付适配和完整Web；这些继续列在后续任务，不作完成声明。

## 6. 研究详情、诊断、单结果导出和请求审计（§47）

TASK-015/020/025/028整包，仍仅synthetic数据。详情`GET /v1/sold/{id}/comps/{event_id}`只接受owner已可读快照的成交ID；诊断沿现有`/diagnostics`最多100条分页，游标签名绑定owner/query/candidate hash。详情不新采集、不收费，不返回原始页面、上游图片URL、对象key、profile/DOM位置或供应商凭证。

字段守卫：当前source_clearance.permitted_fields.research为明确数组，允许identity/title/condition/attributes/description/defects/price/shipping/sold_date/primary_image/listing_url；缺少或非数组视为无逐条展示许可。fixture helper仅为synthetic来源明确写入该模拟范围。每个详情字段返回state=present/missing/withheld与value（后两者null）；说明和缺陷当前未存即missing，禁止从标题猜补。未获identity许可的记录不返回任何行标识，只计withheld_count。已有结果列表、计算输入、媒体和导出同步检查当前字段范围，不能从其他入口绕过。价格/运费/日期缺字段许可时，不分发完整计算输入。

core在同一完整候选资格处理中生成逐条纳排决定，持久化query_comparables。离群候选按未舍入Type7四分位与1.5IQR精确有理数比较，n<8不标；只标不删，不改原stats/hash。新结果直接写决定，旧结果从同一冻结候选/版本补建，不抓新数据。

导出`POST /v1/sold/{id}/export`，body={format:json|csv,view:authoritative|adjusted,excluded_sale_event_ids?:UUID[]}；调整仅接受完整合格输入中的ID、去重上限2000，源集合上限2000/序列化5MiB。权威导出为本快照获准全部价格样本；调整用同一core统计重算，标user_modified=true并保留original_stats。标明完整性/候选hash/版本/时钟/币种/口径/字段说明和排除ID，不改权威结果或收费。缺少逐条价格/运费/日期许可则403；CSV对公式/控制字符前缀转义，所有下载private/no-store，不创建公网可复用下载URL。

请求审计：仅已认证owner的查询路由记录固定operation、入口web/api、request_id、query/job/charge/ledger引用、HTTP状态/稳定错误码、整数耗时、复用/stale/实际本次credits；不存原始URL/querystring/body/关键字、cookie/key/IP或响应正文。账本是扣费真相，审计写失败不得诱发第二次扣费或把已提交claim改写为失败。`GET /v1/requests`按owner和签名游标分页，最多100条，查询日志本身不递归记录；30天可读保留期，清理仅限过期审计行。审计写失败通过不含owner/请求内容的固定错误告警，并保留X-Request-ID以便账本复核；不是承诺跨库原子提交的资金记录。

本机断源边界修正（台账§53）：同owner同规范参数近期复用也必须按请求传入的allow_stale及绑定水位重新检查可作为当前结果的时间窗。已交付历史仍可按独立保留规则读。恢复出现可用新水位时，过期的在途请求释放原dedupe，记录过期并撤销旧lease，不能继续分发。查询费、复用时长和清算原子性不变。

## 7. 客户端的领取、恢复与对账

本机异步路径为 `GET /v1/sold` → 202 → 免费 `GET /v1/jobs/{id}` 到 completed → `GET /v1/sold/{id}`。免费或已交付时最后一步直接返回 200；待领取且需付费时返回 409 result_not_claimed。记录 query_id、job_id、expires_at、本次 request_id；交易日志保留最小必要信息，避免记录密钥、关键词和成交明细。

| 发生了什么 | 调用方下一步 | 可复核账本事实 |
|---|---|---|
| 等待中、轮询超时或应用重启 | 保存 ID 与可恢复状态，在 TTL 内继续查询同一 job。区分终态 failed/cancelled/expired。 | 排队、计算和轮询为 0；单凭 completed 不能认定消费。 |
| 409 result_not_claimed | 向用户显示最多 1 credit。取得同意后生成一个该次命令专用的 16–128 字符可打印 ASCII 幂等键，绑定原 query_id，并 POST 原结果的 /claim。 | 合格、fresh、权利与余额有效时一笔 charge 和 ledger 同事务提交；相同 owner/结果不会多扣。 |
| POST claim 已发出但客户端断线 | 先 GET 原结果；可读时停止。若仍是 result_not_claimed、原授权仍有效且未过期，用原 key 原 query_id 再领。 | GET 本次 0；曾收费由总费用字段与 ledger 对照。查日志的 request_id 关联 charge/ledger，不靠客户端收包推断收费。 |
| 402 insufficient_credits | ready 保留至查询创建后 24 小时。在有效期内补足额度并显式再次领取原结果。402 未提交成功，不永久占用幂等键。 | 失败无 charge；之后成功仍最多 1。 |
| 429 / 503 / 403 / 410 | 429 遵 Retry-After；临时 503 有界退避。无覆盖/过期水位或无权状态要解释原因，当前请求没有合法结果时停止。403 不扩大权限重试；410 未领取已到期。 | 失败免费。历史 GET 逐次重验来源权利、留存及 owner；不能用重放旧响应绕过撤销。 |
| 查看日志及余额 | /v1/requests 按 channel、operation、status 及签名 cursor 分页；error_code 是结果项。用 /v1/usage 核对本次/已提交消费；调用异常带 X-Request-ID。 | 请求日志 30 天可读；日志写失败应在领域事务外告警，账本已提交的领取仍以账本为准。 |

同一 owner 和规范查询在 10 分钟内跨 REST/MCP 重试，候选 hash、资格、结果一致；同一语言切换、重新展示或免费获取旧结果不再消费。研究样本 [58 条可复算过程](搜索页采集字段与统计契约.md) 同时给出改变 limit 的查询身份差异。轮询、收费和 100 并发断言可定位到[领域回归](../tests/query-billing.test.mjs)、[MCP 回归](../tests/mcp.test.mjs)、[请求审计失败回归](../tests/research.test.mjs)。
