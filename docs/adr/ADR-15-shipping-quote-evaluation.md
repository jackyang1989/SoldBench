# ADR-15 · 实时运费报价评估与决策记录（TASK-056 / AT-073）

- **日期**：2026-11-24
- **关联任务与验收**：TASK-056（5 人日决策包之一）、AT-073、CP-24、DEC-16
- **结论状态**：`DEFERRED / NOT_ADOPTED_FOR_LAUNCH`（不纳入首发及已排期 V1 / V1.5 / V2，不将 5 人日决策包当作可售运费估算服务）

## 1. 边界澄清：历史观测运费 ≠ 实时承运商报价

SoldBench 既有的研究与统计链路已经严格建模并隔离历史成交中观测到的运费字段（`observed_shipping_cents` / `shipping_status`：`observed`、`verified_free_shipping`、`unknown`）：

- 当来源明确展示“Free shipping”时，`shipping_status='verified_free_shipping'`、`shipping_minor=0`；
- 当来源未展示或需要登录/特定邮编才计算运费（Calculated shipping）时，保持 `shipping_status='unknown'` 且 `shipping_minor=NULL`，绝不以 `0` 填充或伪造含邮总价；
- “实时运费报价（Shipping Quote Estimator）”是指根据买家目的地 ZIP、包裹尺寸（长/宽/高）、重量以及 USPS / UPS / FedEx 等承运商商业费率表动态计算当前邮费——它既不是已核验的历史成交证据，也不存在于已售快照中。

## 2. 四项评估维度结论

| 评估维度 | 核查结论 | 决策影响 |
|---|---|---|
| 真实用户需求与替代度 | 核心卖家/商家查价诉求是核验商品已成交价格区间（商品价 vs 含已知运费总价）与净价透明度；对于“待售邮费试算”，卖家通常已在上架工具（eBay Label / Pirate Ship）拥有现成实称计费。 | 非首发高频刚需，不应侵占核心供数稳定与准入资源。 |
| 输入完备性（US ZIP / 尺寸重量） | 已售搜索页与多数商品详情页不包含可靠的实际打包重量（oz/lb）与箱规尺寸（L×W×H），发件地 ZIP 常被脱敏至城市或区间；缺少结构化体积重与服务等级时，任何实时估算均具高度误导性。 | 强行推算重量或默认 flat-rate 会破坏 SoldBench“未知绝不猜测/补零”的工程不变量。 |
| 承运商数据源与合同成本 | USPS / UPS / FedEx / EasyPost / Shippo 等官方实时费率 API 均需商业账号注册、费率协议、QPS 配额与按次计费或月费门槛，且严禁在无授权下抓取代算页。 | 当前 `COLLECTOR_ENABLED=false` 且零外部商业账号前置尚未满足，无法通过离线开发解决。 |
| 隐私、统计污染与合规风险 | 收集或持久化终端用户目的 ZIP 属位置敏感数据；若把实时估算运费与历史 `observed_shipping_cents` 混算进均值/中位数，将污染可比快照与 CSV 导出口径。 | 在语义与合规未单独冻结前，禁止与历史成交总额混用。 |

## 3. 正式决定（不实施说明与未来重启前置）

1. **当前决定**：**暂不采纳 / 拒绝在首发及 V1–V2 实施实时运费报价功能**；仅维持现有“历史已观测运费精确记录、未知保持 `null`、按配送范围分别统计且不混合目的地”的研究规则。
2. **明确不交付服务声明**：本 5 人日决策包（TASK-056）**未**编写任何 USPS/UPS/FedEx/EasyPost 实时报价端点、SQL 表或 UI 估算器；网站、文档与定价均不得宣传实时邮费计算。
3. **未来重启前置条件（若创始人后续决定立项）**：
   - 先取得至少一家承运商/聚合商的书面商业 API 许可及实测单次成本（纳入 DEC-07 成本模型）；
   - 单独冻结新接口与独立字段命名空间（建议 `/v1/shipping/quotes`，强制与 `sold_price` / `observed_shipping_cents` 分离展示，绝不进入已售均值/中位数）；
   - 单列 **10 人日**独立工程实施任务及专属 AT（独立输入校验、重量缺失拒接 422、零成本混用防线、目的地隐私脱敏及计费配额），经审批后方可启动编码。
