# ADR-12：离线开发契约冻结与真实接入边界

日期2026-11-16。依据：用户要求现在补齐全部实施缺口，并明确“目前没有，先完成离线开发与准入准备”。状态：**离线实施基线**。不授予外部来源访问、商业再分发或真实收款权限，也不代替G0。原始交付副本见 [v1.4原文](../baselines/SoldBench-v1.4-original.md)。

本ADR将此前技术/产品建议收敛为可编码、可测试的开发契约。对已列出的歧义，执行以下规则；其他范围仍按v1.4。正式上线前须签收实际套餐/条款/来源和支付配置；此类外部输入不是可以由Agent捏造的文档内容。

## 1. 异步交付结算

区分 `compute_status` 和 `settlement_status`。job queued/running没有charge；计算完成job=completed且result_state=ready，尚未结算不能读取付费内容。GET jobs只给状态和claim_url，绝不收费。

新增 **POST /v1/sold/{id}/claim**，owner显式领取；同一事务核验当前权利、新鲜度、版本、余额并创建唯一charge/ledger后返回结果。请求必须Idempotency-Key；成功提交后网络断线仍记已交付，可通过GET result免费复取。服务器无法证明客户端真正收到字节，不以客户端ACK控制记账。

第一次GET result遇未领取的付费结果409 result_not_claimed；匿名/低样本/允许stale为not_required可免费读。同步GET sold的合法即时200仍按原稿统一1credit，客户端明确发起该查询已构成交付请求；缓存预取/爬虫不得触发。

待领取结果从query.created_at起保留24h；届满result_state=expired不可领取，未扣费；已completed job不倒退为expired。未完成job到TTL才转expired。领取时数据已陈旧，原请求allow_stale=true且≤72h则0credit；false则503，不偷偷收费；>72h无当前价。已购买历史仍按自身保留与当前权利免费复取并标history。

额度不足402保留ready至TTL，充值后用新幂等键重试；已完成领取的同key/同query不多扣。幂等成功响应可重放，402/503等未提交业务失败不永久占用key；所有返回仍重查当前访问与来源权利，不能重放被撤销的数据正文。

## 2. 时间和未知事件

固定执行as_of；精确时间窗口 `(as_of-window, as_of]`。仅日精度按来源IANA时区展开半开日区间，必须整个区间确定落窗才计入；跨边界/未知时区保留诊断并排除。源日期本身缺失不能用抓取日充当成交日。

多来源/分页快照data_as_of为本查询参与覆盖分片最后已提交水位的最小值；失败分片不推进水位，保留partial。source_window和truncation明确返回。没有分片水位则unknown，不用任意最新记录假fresh。

无独立event key时，可按稳定listing+来源日期/精度+获准证据指纹记录一条uncertain观测候选；默认不进入可比事件和价格统计。跨来源未证明同/不同事件时先按已核验单来源范围返回，不能直接拼出更大市场销量。人工核验有独立成交依据后新增identity版本，不改原始观察。

## 3. 额度和退款开发默认

Free账户邮箱核验成功发100credit，UTC核验日作为月周年锚点，月底无该日则截到当月末；每期唯一grant，登录/刷新不发。付费升级只发已确认支付的新付费周期额度，关闭本期Free桶并expire剩余额度，保留购买/promo；重复回调不重复发。取消订阅期末生效，降级期末再开始Free周期；正式渠道有强制不同规则时先更新版本再实现。

query credit退款：原桶有效返原桶；已过期返30天promo补偿桶。每charge最多补1credit，原ledger只追加反向项。cash退款是独立事件，不能由credit退款自动触发。

按量购买现金退款：首发不提供用户自助部分退款；正式政策签收前仅模拟全额退款/争议。渠道确认退款时原grant桶的未用部分用expire/adjust撤销；已用部分记在单独credit_recoveries（不让wallet负数），暂停新收费查询和新增grant消费，进入人工复核；不删已买结果或篡改旧charge。复核通过补偿/豁免/渠道最终状态消除recoveries后恢复，所有命令有原因和审计。订阅退款按同一原支付周期grant定位处理；不能凭收到退款事件重复扣其他购买桶。

## 4. 其他实施默认

分享默认24h、最大7d，只分享权威结果；源许可更短则取更短。验证token24h、重置token30分钟、重发60秒冷却/每账户每小时5次；会话7日绝对期限、管理员12h，敏感操作需10分钟内重新认证/MFA。真实邮件供应商未定，统一adapter与本地outbox，不能显示真实送达成功。

匿名5次/UTC日只计成功交付的缓存查询（含低样本）；同匿名身份/参数10分钟复用不重复计次；错误和未命中不消耗日次数但计入防刷速率。

离线性能基线使用固定数据规模和资源记录；预发布建议API/DB各2vCPU4GB、独立Collector作为目标配置，部署与预算由实际批准确定。恢复目标暂按RPO24h/RTO4h编写测试，最终必须实测签收，不能写成已达到SLA。

## 5. 冻结交付与权威顺序

文字规则→ [OpenAPI](../openapi.yaml) / [SQL基线](../contracts/schema.sql) →关系与schema用例必须一致。本ADR明确消除DEC-01/02/03/04/06的离线编码歧义；DEC-05/07/08中的真实权限/账户/商务内容继续作为外部前置，不能通过更名状态伪装已解决。

原规格相关段落已指向本ADR。未来改变金额/收费/身份/时间语义需新的ADR、版本和回归；当前设计版本为contract1.1，engine/cleaner/billing的运行版本在产品实现时按实际差异升级。本轮没有生产运行版本发布。
