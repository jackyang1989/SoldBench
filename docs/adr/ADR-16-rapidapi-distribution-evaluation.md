# ADR-16 · 第三方 API 分发渠道（RapidAPI 等）评估与决策记录（TASK-056 / AT-073）

- **日期**：2026-11-24
- **关联任务与验收**：TASK-056（5 人日决策包之一）、AT-073、CP-24、DEC-17
- **结论状态**：`REJECTED_FOR_LAUNCH / DEFERRED`（首发拒绝通过 RapidAPI 分发，保持自建 Stripe + PayPal 直营计费与 OAuth/API Key/MCP 体系）

## 1. 渠道评估范围

评估将 SoldBench REST API（`api.soldbench.com/v1`）上架至 RapidAPI 等第三方 API 聚合交易市场作为获客与收费分发渠道的可行性，重点对照平台抽成、商户主体（MoR）/税费/退款/争议赔付、计费语义一致性以及上游数据再分发许可条款。

## 2. 四项结构性冲突分析

| 评估维度 | RapidAPI 市场规则与事实约束 | 与 SoldBench 架构及政策冲突 |
|---|---|---|
| 平台抽成与单位经济（DEC-07） | RapidAPI 对交易额收取约 **20%–25%** 渠道佣金（另含提现与汇兑摩擦），而在真实采集代理/IP/人工核验成本尚未完成 14 日实测前，毛利安全垫尚未确认。 | 在高单次采集与合规成本模型下，直接让渡 ~25% 毛利会使小额低单价套餐陷入负毛利风险。 |
| 计费原语与幂等模型不兼容（ADR-12 / DEC-01） | RapidAPI 代理网关按“HTTP 请求命中/配额计数”计量；无法感知 SoldBench 内部 `POST /v1/queries/{id}/claim` 显式领取原子扣费、轮询 `/jobs/{id}` 免费、10 分钟同参数复用免费、`<8` 低样本免费及主动 `stale` 确认免费语义。 | 若通过 RapidAPI 网关直接按次计费，将导致低样本/失败/轮询误扣费或引发双扣账，与现有唯一真实账本 `credit_ledger` 冲突。 |
| 税费、退款、拒付与 MoR 边界（DEC-02 / DEC-07） | RapidAPI 作为市场代收与按月结算方时，SoldBench 丧失单笔实时争议拦截（`credit_recoveries` + 争议期暂停新消费）与原 Stripe/PayPal 支付流水精确对账能力，退税与拒付通知存在结算延迟与不可控扣回。 | 违背“自建账本与渠道全额退款/争议联动冻结”资金不变量，亦与 Stripe 主 / PayPal 辅的既定支付决定冲突。 |
| 数据来源再分发与平台条款（DEC-05） | 第三方市场条款要求服务方声明具备公开发售与经该平台再分发的完整权利；若上游来源限制禁止第三方 API 目录转售，或要求立即撤权下线（Epoch Revocation），市场缓存与代理转发层会增加撤权滞后风险。 | 首发前在来源许可及企业再分发范围未完全获批前，接入第三方分发市场会放大法务与撤权责任。 |

## 3. 正式决定（不实施说明与未来重启前置）

1. **当前决定**：**首发及当前路线阶段拒绝接入 RapidAPI 或同类第三方 API 代销分发渠道**。开发者与 SaaS 客户统一经由自建官网（`https://soldbench.com/docs`）、个人 API Key（`Bearer`）、OAuth 2.1/PKCE 与 Hosted MCP（`https://soldbench.com/mcp`）接入，并统一使用自有 Stripe/PayPal 结账与 `credit_ledger` 计费体系。
2. **明确不交付服务声明**：本 5 人日决策包（TASK-056）**未**实现 RapidAPI 代理密钥头校验、RapidAPI webhook 适配或独立计费通道；OpenAPI 与线上产品不对外承诺 RapidAPI 套餐或代理入口。
3. **未来重启前置条件（若增长阶段重新评估渠道分销）**：
   - 仅开放“按结果包/固定预付配额兑换”的同步受控方案，绝不允许第三方代理直接绕过 `POST /claim` 按裸 HTTP 请求扣费；
   - 先完成 Stripe/PayPal 主渠道稳定收款、真实单位经济核算（确认让渡 20%–25% 抽成后仍满足最低毛利底线）、税务/MoR 条款审核及上游来源明确书面允许经第三方 API 市场再分发；
   - 单列 **8 人日**独立集成任务（签名代理鉴权、对账适配器、独立争议与撤权同步契约及专属 AT），经创始人签字解锁后方可执行。
