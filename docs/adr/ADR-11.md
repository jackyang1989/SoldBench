# ADR-11：v1.4 实施解释、冲突登记与任务入口

日期：2026-11-15。状态：本轮文档工程基线；不代表创始人商业批准。原始规格保持不变，由本 ADR 显式列出解释，未裁决项继续 OPEN。

## 已明确的工程解释

1. 原稿 §8.3 的“订阅→purchased→promo”与 §11.2、E-15 冲突；遵照原稿 §0 的资金裁决顺序，采用 §11.2：有限期桶最早到期优先、同日订阅优先、purchased 最后。对应 AT-028。
2. `docs/progress.md` 作为台账入口，唯一可写任务状态在开发排期文档；保留 S-01…S-27 及原 T-0 编号，不重复建进度。
3. S-14 完成判据的 `GET /v1/jobs` 按 §9.2 解释为 `GET /v1/jobs/{job_id}`；无独立 jobs 列表产品承诺。
4. limit 只影响展示，统计和 1 credit 不按条数截断；前端只有 50/58 条时不能声称“在全部 58 条上剔除重算”。见工程规格的完整集合与展示子集方案。
5. 排期中重叠的原周次仅为旧估算。本台账用单实施线 E 日顺序，阶段门未过不进入下一阶段。14 天在线观察、7 天生产采集稳定期及第三方等待单独计时。
6. 原稿要求第 0 步模拟账户/账单可用，同时禁止正式账户/账单实现。第 0 步只验证隔离和断源接口模拟，不提供账户安全或计费上线证据；真实全链路在 S-26 再验。不得为前置演练提前开发产品。
7. 原稿称 DB 设计“可执行模式”，实际仅字段表，没有 SQL；未生成并实测 SQL 前不称迁移通过。同理原稿节选 JSON 不是完整 OpenAPI fixture。

## 尚不可自行裁决

2026-11-16更新：异步领取、过期补偿、退款恢复、时间及身份的离线规则已由 [ADR-12](ADR-12.md) 冻结。真实来源许可/支付审批仍是 [决策登记](../决策登记.md) 的外部前置；不将开发默认当商业GO。

## 回退及维护

原稿未覆盖写入；撤销某项解释时在本 ADR 追加 superseded 记录并修订受影响规格、AT 与任务，不删除已留的执行证据。新增产品需求需更新原稿版本，不借 ADR 扩大首发范围。
