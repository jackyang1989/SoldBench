# 工程实施规格

实施补充1.1，2026-11-16。原稿§4–9/11/13及 [ADR-12](adr/ADR-12.md) 为离线实施基线。已提供 [完整OpenAPI](openapi.yaml)、[SQL设计基线](contracts/schema.sql) 和关系/静态验证；活动工作区包含 `apps/`、`packages/`、CI 和离线运行命令，见 [README](../README.md)。下文规定工程目标，当前落地与证据以任务台账为准。用户已按 [ADR-13](adr/ADR-13.md) 授权完整离线产品工程，真实来源与支付/发布仍待实际准入。

2026-11-17认证实施以[账户访问契约](账户与访问实施契约.md)和[ADR-14](adr/ADR-14.md)补齐；认证cookie不进入通用明文幂等缓存，单次token与key首次展示采用各自重试规则。查询/账务仍遵ADR-12。

## 1. 架构与模块责任

延续 TypeScript monorepo、Hono API、React SSR、PG16、Redis/BullMQ、S3兼容存储、Docker Compose。TASK-011 核对实际兼容版本、锁包和运行时；不照抄 qcwarehouse 的 Next.js，也不依赖它的目录。Web SSR 实现方案在该任务形成 ADR 并锁版本，不引入第二套业务后端。

| 模块 | 输入/输出 | 必须拥有的规则 | 不承担 |
|---|---|---|---|
| `packages/shared` | schema、错误、版本、pricing | query DTO、scope、套餐/限额唯一配置 | DB 查询/供应商调用 |
| `packages/core` | 可重放规范输入→匹配/统计/诊断/hash | 价格资格、Type7、trim、质量分项 | 网络、时钟、随机数、收费 |
| `packages/collector` | 有效许可/预算/任务→观测与证据 | guard/fetch/parser/page/identity/circuit | 发客户权益、绕限制、自建之外代抓取 |
| `packages/db` | repository、事务、migration | FK、唯一键、锁、outbox、不可变账本 | UI 状态 |
| `packages/billing` | charge/grant/refund/expire 与渠道事件 | 钱包顺序、幂等、对账 | 重新实现统计资格 |
| `apps/api` | Web/REST/MCP调用→共同查询服务 | owner、scope、限流、统一错误 | 同步等待 Collector 网络 |
| `apps/worker` | outbox→清洗/快照/通知/删除 | lease、重试、恢复、版本重放 | API 主进程生命周期 |
| `apps/collector` | 自研采集独立进程 | 网络出口/资源隔离、停机开关 | Web 可用性 |

## 2. 查询规范化与快照

1. 按 allowlist 解析参数；未知 `attr_*` 拒绝，不能悄悄忽略。q 去首尾/合并空白/NFC；不盲目排序词语，不删除型号标点。品牌别名仅使用版本化类目词典。
2. 显式补齐 marketplace、window、price_basis、limit、allow_stale 默认值；枚举和布尔严格解析，filter map 按键排序；排序不改变字符串内容。
3. 规范 JSON UTF-8 做 SHA256；owner+规范 hash 为10分钟请求复用身份。不同 owner 不共享 query_id、收费和历史；同 owner 不同 key/入口可复用。
4. hash 纳入 limit、allow_stale、所有过滤、normalizer version；复用还要求 engine/cleaner、许可版本、新鲜度策略相容。`now` 不进入参数 hash，但快照固定 `as_of` 并记录执行时间。
5. 复用窗从 query.created_at 起算 `[t,t+600s)`；不能按最后访问不断延长。窗口外新 query 可使用同一底层数据但独立收费资格。完成前重复请求返回同一个活动 job。
6. 底层数据缓存 hash 不含 owner、key、账务；含源/许可版本、属性/窗口/口径、cleaner/engine、新鲜度策略、候选 cutoff。任何 cached DTO 必须重新套 owner 授权和收费元数据。
7. `candidate_set_hash` 对排序后的 event identity、输入金额/费项/日期/资格、各版本及固定 as_of 计算。排序 key 为 source_id、event_id；不只 hash UUID，否则修价后无法检测。
8. 输出顺序独立固定为 sold_at DESC NULLS LAST、sale_event_id ASC；limit 截取输出不截断统计集。离线及首发设计每查询候选上限1000、保留可展示comp最多200；达到源/本地上限标 partial/truncated，不能标 complete。上线成本门可收紧上限，须同步契约/文案并重验，不可悄悄截断。

第3–5项的统一实现和10分钟边界由 TASK-002 定版，版本策略不得造成免费无限复用或重试双扣。查询参数拒绝原因必须在接口 details.fields 中定位。

## 3. 事件、时间和数据身份

生产与夹具是两个 schema。夹具缺少的生产字段不能补成“已核验”。生产事件需 source、observation、许可引用、币种、日期精度、价格证据、身份状态；不合格记录进 quarantine/diagnostics，不能偷偷丢弃后缩小 `n_observed` 使报告变好。

有稳定 source_event_key 用来源+事件键唯一；同 listing 多事件需独立证据。无事件键按ADR-12记录uncertain候选并默认排除可比/价格统计；原始 hash 相同只表示内容相同，不能据此把所有同价销售当同笔，也不能把重复抓取当新增成交。跨来源未验证重叠不能直接拼接声称完整市场样本。

日期：原文、来源时区、精度和转换版本一起保留。UTC存储并不意味着把未知时区日期当UTC午夜。ADR-12规定整日区间完整落在滚动窗口内才纳入，否则列 `date_boundary_uncertain`；所有边界用注入时钟验证。固定fixture采用已给 UTC sold_at，仅验证原有算例，不证明生产日期归一正确。

freshness 依据一次完整/有解释的部分采集覆盖水位，不是 sold_at 或某条最新返回时间。分片中一条新记录不能使旧片段变fresh；按ADR-12采用保守水位并写明partial原因。`data_availability` 是投影，每次出数仍按当前权利和时钟校验，不能只依赖定时任务过渡状态。

## 4. 统计契约和排除对账

按照权利→身份/时间→全局属性→强约束→价格资格→统计顺序处理。每条记录保存所有诊断 reason，但对账只取固定优先级的 primary_exclusion_reason；多原因不能重复累计。

```text
n_observed = n_excluded_before_comparable + n_comparable
n_comparable = n_price_verified + n_excluded_unverified_price
sold_last_30d_observed <= n_price_verified
returned_comp_count <= min(limit, permitted_comp_count, n_price_verified)
```

资格不足或币种/运费缺失均归入价格排除，同时细分 missing_shipping/unverified_actual_price/missing_fx。source权利不足的内容不向用户暴露；对外只给允许公开的聚合原因。n_observed包含去重候选，uncertain在可比之前排除并单列身份未知数量，不人为抬高成交数量。

金额：来源十进制字符串用精确 decimal→整数源币最小单位；USD转换按有证据历史汇率，保留精度。统计内部用 bigint有理数；输出前检查不超过 JS safe integer；超界拒绝并报警，禁止无损声明后直接 Number(bigint)。禁止按当前汇率伪造历史价。

Type7：`h=(n-1)*p`，相邻整数价格线性插值，最终非负 half-up；median偶数同样规则；trim `k=floor(n/20)`，均值取 `[k,n-k)`。n=0 min/max也null；n<8四项中心统计null；8–29 limited；≥30 sufficient。离群候选保留在默认分布；IQR为0不自动删除所有不同价。

固定黄金夹具 expected_stats全字段精确匹配：121/64/58/6/35，median5800/p254200/p757600/trim5930/min2900/max10800，fixed54/verified_offer4/displayed_offer6，verified_share0.90625，覆盖/总分null。完整数值以原文件为测试真值，不把58固定进引擎。

## 5. 前端重算与返回条数

服务端提供权威快照；F-04需要获得完整可重算输入，不能只用limit=50的列表去重算58条。提供owner免费接口 `GET /v1/sold/{id}/calculation-inputs`，返回已购买/允许读取快照中全部统计资格事件的event_id、price_usd_cents、sold_at、sale_format以及原候选摘要，不增加原始敏感字段。最多达到冻结候选上限，返回完整标志/hash/版本；是否能分发这些输入须逐源允许。

前端用同一core包按排除ID重算；显示user_modified、原始hash、剩余统计样本数、本地范围。未取全/无字段许可时只能标“loaded sample only”，不得冒称完整；F-04完整体验的首发来源应满足输入许可，否则由产品负责人明确缩减能力并修订验收。

权威分享仅分享原快照；用户调整结果不作为正式价格，首发不提供可长期保存的调整快照。客户端计算无新charge、不修改数据库、不宣传置信评分。空/低样本调整复用统计阈值。

## 6. 查询与作业状态

| 对象 | 状态/迁移 | 关键守卫 |
|---|---|---|
| 来源准入 | draft→reviewed→active→suspended/expired/revoked | active必须含有效证据/范围；后台不能自动补授权 |
| Collector circuit | closed→open→half_open→closed | 权利/挑战失败必须人工批准探针；普通网络故障仅在许可和预算内有界重试 |
| collector_job | queued→running→completed/failed/cancelled | lease到期可接管；每次外发重新guard；不允许恢复旧权限快照绕过当前撤销 |
| query_job | queued→running→completed/failed/expired/cancelled | 计算完成只变ready；POST claim后结算，24h待领取有效期，终态不能被迟到worker覆盖 |
| query settlement | uncharged→charged→refunded | query唯一charge；低样本/stale/失败永不charged；退款用反向流水 |
| share | active→expired/revoked | 来源禁分发高于share的active状态 |
| payment_event | received→processing→applied/retryable/failed | 验签先行、唯一event、乱序后主动对账，不按到达次序直接改权益 |

客户端断线不等于取消；取消命令锁job/版本，已结算完成返回409，未完成取消释放排队资源，迟到结果不能再收费。请求重试与用户新查分开：恢复原job不新收一次；明确“新查询”才按新参数/窗口算，且仍受10分钟复用规则。

查询流程：鉴权/限流→参数规范化→owner复用锁→有效旧query→可读缓存→来源/预算检查→写query+job+outbox→202。同步缓存走同一结果发布/结算逻辑。没有可恢复采集能力时503，不创建无限排队；允许实时路径超过15秒返回202；应用请求超时不触发第二个采集任务。

按ADR-12，compute_status=completed不意味着已收费；result_state=ready/available/expired/forbidden与settlement_status独立。POST claim承担首次交付，GET jobs永不收费；GET结果对未领取付费结果返回409 result_not_claimed。已completed的job不因领取TTL到期倒退为expired；结果状态独立到期。

本机以 `worker_heartbeats` 保存查询 worker 最近完成处理循环的时间。`/ready` 用同一 PG 时钟检查最近心跳和是否存在超过等待界限的可运行查询。探针与主管进程不修改查询阶段、租约、预算或账本。就绪信号、告警和恢复动作见[发布、回滚与撤权恢复手册](发布、回滚与撤权恢复手册.md)。

## 7. 事务、outbox和重放

- 创建query/job与outbox同一PG事务；dispatcher按唯一事件投BullMQ。消息可以重复投，不能丢业务事实。
- 领取job用lease_owner/lease_until/attempt/version；提交用CAS版本检查。超时worker恢复后不能覆盖新worker、取消或过期结果。
- 付费发布同事务核验当前用户/许可/结果资格→锁相应wallet按稳定顺序→插唯一charge→减余额→插ledger→固定result/交付状态→outbox。事务失败所有步骤回滚。
- DB余额是事实源；Redis不能独立扣款。账本不可update/delete；wallet balance与ledger和charge每日及恢复时对账。
- 底层来源数据缓存可安全跨用户复用，但不同owner各自获得query和收费。共享采集任务不共享owner DTO；任一用户取消不删其他用户仍依赖的底层工作。
- outbox和payment事件去重键有命名空间；同Idempotency-Key不同body返回409，相同body重放原业务结果。任务跨10分钟窗恢复仍不能再次charge同query。
- 队列损坏从DB恢复pending outbox；原job已终态的旧消息消费为空操作并留指标。不能通过重试无限扩source日预算。

## 8. 权利、缓存和删除

source_clearance需要revision、allowed_operations、field_permissions、effective/expires、存储/公开/统计/API/分享分别许可、保留及终止政策引用。记录准入快照用于审计，但出数遵循**当前有效权限与历史保留约束交集**。

撤销事务先将source blocked并提高permission_epoch，读链立即拒绝；后台再清Redis、派生结果、分享、SEO/CDN和对象文件。不能等异步删缓存才开始拒绝。跨来源混合快照整份阻断，随后生成新的允许子集版本，不改旧hash。账本保存最小query标识，不存商品内容副本。

原文与派生字段不同保留策略；未知保留期限不得当永久。tombstone以最小对象ID/hash保留审计，不存需删除正文。备份不可逐条删时必须隔离到期和恢复删除清单；恢复后先执行当前撤销/删除，再开放读链。引用合同/法律的具体期限走DEC-05/08。

浏览器第三方分析不得收query文本、token、email、key。分享token只存hash、日志路径裁剪、no-store/no-referrer/noindex；不把token写sitemap。S3原文私有，短期签名读取仍需先授权，禁止公开桶。

## 9. 认证与计费实现细节

认证的具体密码库/哈希参数由TASK-023按当前官方文档与性能预算选择；禁自制密码算法。会话HttpOnly/Secure/SameSite、服务器撤销、CSRF/Origin检查；密码重置单次token仅存hash，候选TTL30分钟；验证邮件token候选24小时；重发冷却60秒/小时上限，参数集中。API key使用高熵随机密钥、前缀识别+安全哈希，禁止完整key日志；撤销≤60秒，账号停用即时拒绝。

会话/API限速分层：入口防刷→owner/key速率→每日匿名/来源预算→credit资格；429说明是哪层及恢复时间，不泄露其他用户负载。Redis故障采用安全的PG额度/限流降级或拒绝新耗费请求；key管理/账单读取继续可用，不全站依赖缓存启动。

匿名次数的工程默认：仅在有效缓存结果成功交付时消耗一次（低样本结果仍属一次匿名查询），参数错/缓存未命中/503不消耗每日次数但计入防刷速率；同匿名capability同规范参数10分钟复取不重复消耗。用PG唯一identity/day行锁或原子更新限制used<5，再持久化交付结果；失败事务回滚。身份依旋转IP哈希与第一方Cookie联合判断，不只依Cookie。该规则须在TASK-031的页面说明与AT-034同步，变更按产品规则登记。

grant唯一身份为(user,grant_kind,provider,period/payment_id)，Free用稳定UTC账期起点；policy_version只作为发放快照，不参与可变唯一身份，防止换策略后重放旧付款再发权益。Free从邮箱核验日UTC月周年锚点，升级/降级及月底截断按ADR-12。消费排序采用ADR-11；到期任务与扣费锁同wallet，过期余额写expire流水后归零。purchased无expires不参加订阅清零。补偿需要reason+original_charge，现金退款与credit refund分别存状态及渠道引用。

webhook按渠道官方协议验证原始body与签名；具备签名时间戳时验证时间窗，不能把未签名的事件created_at当成防重放依据。无签名时间戳的渠道依持久化事件去重及状态复核处理重放；持久化后2xx，持久化失败5xx让渠道重投；异步处理失败可重放。未知事件不发权益。`last_provider_event_at`不能独自防乱序：用渠道对象最终状态、周期与支付ID确认；主动对账禁止由前端传价格/额度。用户最终决定Stripe主支付＋PayPal补充；Creem/Dodo只核验备用资格。遵循 [支付接入规格](Stripe与PayPal接入规格.md) 与OpenAPI1.4.0：独立验签/事件映射，owner跨渠道订阅checkout锁、支付业务键唯一grant，订单/订阅/退款固定归原provider。两个通道分别审批并验收后启用，不自动故障切换账务；销售税/发票责任按直连支付方案落实。

## 10. 部署、监控与成本

配置清单继承原稿附录C；新增SESSION_SECRET、TOKEN_HASH_PEPPER、MAIL_PROVIDER、MAIL_FROM、APP_BUILD_SHA、SOURCE_PERMISSION_EPOCH、JOB_LEASE_SECONDS等由脚手架定义并脱敏验证。不在.env.example填真实值；生产启动拒绝fixture模式、禁用guard等不安全组合。

监控分三类：服务可用（API/登录/账单）、数据可用（各类目fresh/stale/forbidden）、商业正确（charge/grant/refund/成本）。P0越权/双扣/撤销立即停相应读写，P1全源中断30分钟响应；数据库或Redis事故不能伪装成仅Collector断源。

SLI定义：API availability以自身可用请求计，来源503另报data availability并公开二者分母；不能通过移除503制造“供数99.5%”。P95缓存≤800ms、可实时≤15s；测试需给50并发缓存、100并发资金及预发布资源（DEC-11确认）。客户端LCP4G≤2.5s，统计重算最多冻结上限记录<1s。

成本每个run记录成功与失败的请求、页数、网络、CPU、存储、维护、授权费；查询成本包含免费与失败分摊。压力组合必须含Pro10000次/缓存≤30%/长尾多页/低样本免费失败，不能拿70%命中假设当实测。预算耗尽明确503/延迟，不能默默无上限亏损。

## 12. 成交主图采集与交付（用户明确必需）

主图是成交证据的一部分，不是页面装饰或可有可无的增强项。每条 `Comp` 可以携带一个 `primary_image` 状态对象；只能绑定相同listing的primary角色，不能把广告图、gallery顺序图或相似listing图误配过来。多图详情若之后获得授权，可在独立详情契约中追加；首发卡片仍只选主图。

### 12.1 数据与状态

- `listing_images` 外键关联来源、listing、observation及对应的`sale_event_id`；组合外键保证成交事件与图片的listing/source/observation完全一致。输入候选与输出DTO必须携带同一组身份。保存主图角色、状态、受限密文URL（应用层AES-256-GCM）或URL hash、规范对象key、内容hash、规范MIME、像素尺寸、字节大小、抓取时间、存储到期、许可revision/epoch。原始URL和对象key不进入普通用户API、日志、分析或分享。
- 已有库的明文URL升级流程必须按序执行：先运行`npm run db:migrate -- 0003_image_source_url_ciphertext.sql`只增加密文列；设置`DATABASE_URL`和外部KMS提供的`SOURCE_URL_ENCRYPTION_KEY`（32字节base64），运行`npm run db:encrypt-image-urls`；命令以单实例advisory lock + 小批次事务完成AES-256-GCM加密，在清空明文前逐行解密比对，随后全表认证解密密文并确认明文余数为0；保存不含URL/密钥的JSON对账输出后才允许运行`npm run db:migrate`应用`0004_image_rights_hardening.sql`删除明文列。工具可重跑，错误时事务回滚；不得在命令行参数、日志或仓库保存密钥。先在独立上一版副本演练并备份，未知/不可解密记录必须停止迁移并保留数据库原值。
- API和数据库共用状态枚举 `pending / available / missing / failed / not_permitted / revoked / expired`。没有授权与源页面确实无图是不同状态。图像获取失败不改变成交行身份、价格统计、可比样本、缓存身份或credit；相同成交观察后来补到主图，只更新媒体对象。媒体对象必须绑定`listing_id + observation_id + role=primary`，不能只保存图片URL/hash而丢失成交证据来源。
- 媒体采集权限、对象保存权限、变换处理权限、用户展示权限、API/MCP分发权限、分享权限分别判定。没有相应权利即0图像请求；不得用临时重定向、源站直链或页面缓存绕过拒绝。
- 私有对象存储；读URL为短期、owner绑定、当前许可校验的SoldBench媒体路由/签名引用。代理访问每次检查source blocked、permission epoch、用户/分享字段范围、保存和展示期限；先拒绝再异步清除。外部图片缓存/CDN只有在明确许可且支持即时失效时才能使用。

### 12.2 获准后网络获取的硬边界

当前实现提供主图候选绑定、图像解码原型、默认禁用transport与许可纯函数预检；它不能被描述为已授权或已能在线采图。许可纯函数预检**不是并发预算预留或网络派发许可**。未来唯一自托管adapter须使用PG事务锁定并重读当前clearance/source/config/circuit，原子预留请求/页/字节/并发预算，提交前冻结permission snapshot；发请求前复核状态，撤销/熔断时停止后续页和分发。缺少这个持久化预留实现，真实Collector必须继续关闭。图片URL仅密文保存；图片对象绑定listing和observation。每个响应图片地址做HTTPS/精确主机allowlist校验；禁止账号口令、任意port、IP literal、localhost/private/link-local/reserved地址。IPv6分类未完整建模前拒绝所有IPv6结果。

传输必须显式禁用redirect并拒绝任何3xx；连接前解析A/AAAA并禁止回环、私网、链路本地、组播、保留地址，连接时固定到已校验目标并保持TLS主机校验，以防DNS rebinding。仅允许source contract规定的精确host集合；不允许外部输入任意域名。当前IPv6特殊用途规则尚未完整实现，因此A/AAAA记录中出现任意IPv6地址时先拒绝，待完整注册表及测试落地后再解除。设置连接/总时限、流式5MB硬上限、并发/每query/每日预算和取消信号；读取前、读取后、对象发布前各重新检查当前权利/epoch。401/403/挑战/登录墙熔断来源采集并阻止图像及商品字段继续请求，不能改账号/IP/代理后重试。

解码检查真实格式与MIME，拒绝SVG/HTML、动画、截断/多帧未批准格式、解压像素炸弹和解码器警告；受限像素上限，旋转方向后去EXIF/GPS及全部元数据，再生成经允许的固定WebP尺寸，不放大、不输出原图；校验解码大小、输出字节并算SHA-256。对象key不可从用户输入拼路径。孤儿对象清理由DB状态和权利tombstone驱动，不能反向公开。

### 12.3 API与网页显示

所有成交行中 `primary_image` 是可选追加字段，但当存在时必须给稳定状态和可空的受控 `url`、尺寸；不能返回上游图片URL。MCP按同一字段许可返回缩略引用或无图状态。分享DTO默认不包含图像URL，只有来源许可明确允许且分享token权限匹配时才可以含短期展示引用。没有授权展示时UI显示本地通用占位与双语“图片不可用/未获展示许可”，不报broken-image图标，不因此隐藏有效成交记录。

图片alt由可展示的商品标题生成并做长度限制；装饰性无标题图片使用空alt。图片宽高由服务端探测填写，卡片固定比例并延迟加载，详情按需读取；失败状态可重试的仅是权利仍有效且预算可用的媒体任务，重试不再发起商品搜索或扣query credit。

AT-056是媒体从源字段提取、许可前0网络、限时下载、内容验证、对象落库、owner/API/MCP读取到撤销清理的整链验收。媒体网络正向测试只能使用本地合成源或获准的隔离测试源；真实eBay主图端到端验收仍由G0和对应在线门单独签署。

## 19. V1 部署、角色与密钥实施说明

适用 TASK-011/012/017/023/038/042、RC-01。基础 [Compose](../infra/compose.prod.yaml) 以 production 运行形态启动隔离环境，声明 `SOLDBENCH_ISOLATED_DEPLOYMENT=true`、`offline_fixture`、支付和邮件 offline，使用内部网络和 `.test` 主机名，所有服务均无宿主端口。它拒绝同时启用正式门、支付夹具、代理和外部数据业务。正式 [边缘覆盖文件](../infra/compose.edge.yaml) 只在原阶段门与正式环境批准后启用。覆盖后必须通过正式运行配置，Caddy 才能随就绪 API 启动。实际 DNS、TLS、接警和商业渠道另签。

- 数据库按 `PostgreSQL → db-bootstrap → migrate → API/Worker → Caddy` 启动。启动管理员只用于引导，API 和 Query Worker 共享 `soldbench_runtime`。迁移由 `soldbench_migrator` 执行，Collector 和备份分别使用 `soldbench_collector`、`soldbench_backup`。容器通过卷内 Unix socket 与 SCRAM 验证连接，PG 无 TCP 监听。部署迁移脚本核身份、应用原迁移、再应用受管理的权限表。应用读迁移摘要，Collector 限数据域，对共享 Outbox 仅可读写采集事件，备份角色只读。首次部署与升级均须验证旧权限、业务读写和账本不可改写。 [角色引导](../infra/db/provision.sql) · [运行权限](../infra/db/runtime-grants.sql)
- 旧卷沿实际已存在的启动管理员进入引导。先核备份和目标库标识，在隔离副本迁移 `public` 对象归属，核对原迁移 SHA、对象计数和业务权限。再轮换各受管登录的密码，重建各运行服务验证新会话，通过后由平台责任人处置旧应用登录及旧管理员引用。数据库回退回复制和权限快照，不退回使用管理员运行应用。新旧数据库目标或旧版镜像涉及状态变化时，先按 [恢复手册](发布、回滚与撤权恢复手册.md) 核对账本、退款与撤权水位。
- 设置 `SOLDBENCH_SECRETS_DIR` 指向受控目录，角色密码为五个单行文件 `db-bootstrap`、`db-migrator`、`db-runtime`、`db-collector`、`db-backup`。生产从密钥服务物化为只读文件。Host 目录仅部署者可读写，文件权限应允许映射容器用户读取。Auth 文件 `auth-bundle.json` 由 API 和 Worker 以同一版本只读挂载。文件只包含 `version`、`tokenPepper`、`encryptionKey` 与可选 `decryptOnlyKeys`。密钥为 32 字节随机值的规范 base64。版本与 `AUTH_SECRETS_VERSION` 必须匹配。仅允许受控属主/只读组读取 Auth 文件，建议 `0400` 或 `0440`，禁止软链接及修改已发布的同版本内容。
- 加密轮换先让所有进程读得懂新旧密文，再切到新写入键，旧键只读直到存量和受保留备份生命周期结束。回退也保留当期读键。在相同部署域保持 HMAC pepper 稳定，保护会话、API key、幂等和删除清单的验证。pepper 泄露按安全事故失效与迁移检索相关凭据，再同步备份恢复钥匙。缺文件、错误版本、坏格式直接拒绝启动，日志只记录错误类别。
- 商品源 URL 密钥仅供 [加密回填命令](../scripts/encrypt-image-source-urls.mjs) 读取，`SOURCE_URL_ENCRYPTION_KEY_FILE` 是正式执行路径。开发可沿用现有单个环境值，文件与环境值互斥。先验证历史密文一致性再改明文行。数据库转储在文件写入时校验、对账乃至发布前应锁定实际备份目的地的加密与恢复密钥版本；转储工具的 SHA 校验提供完整性证据，存储加密及独立故障域沿 RC-09C 另验。
- 默认 API 监听容器 `0.0.0.0:3000`，只由代理和内网访问。镜像/Compose 探针与 Caddy upstream 都验证端口 3000 的 `/ready`。Query Worker 心跳由数据库读回，独立于 HTTP 就绪。生产启动不等待 Redis，现有队列与账本使用 PostgreSQL；开发用 Redis 容器保持可选。本地事务邮件仍落合成队列。部署示例只公布实际消费的配置，站点与 API 的正式示例域和客服沿用户已定目标。

隔离容器验收执行 `bash tests/compose-runtime.sh`。其用随机测试密钥和唯一 Compose 项目，撤出时只清理本次项目的临时卷。配置检查和本机 PG16 端到端可先记录，真实 Compose、独立复核及目标 CI 作业各按执行事实签收。
