# 国际站点规划与品牌评估

日期：2026-11-16。性质：发现缺口及待评审的扩展方案，不是新增首发承诺或更名决定。六类目标客户以当前原稿§1为准；正式产品仍待G0。国家站点、功能和品牌决定分别处理，不能因改名暗中扩大采集或发布范围。

## 1. 当前缺口

原稿§2将第二市场放在V1.5，eBay UK/DE放在P2，附录E-06又将Mercari列为第二市场默认调研项。现有43任务只覆盖美国站首发，尚无国际站点的工作包、站点成本和独立验收计划。这是后续规划缺口，不意味着美国站已实现或可以直接发布更多站点。

应区分两个维度：同一平台的国家站点扩展（eBay US/UK/DE等），与新增交易平台（Mercari、Poshmark等）。两者都需验证，但字段、身份和解析差异的范围不同。原稿当前阶段归属维持原样；将同平台国际站点提前列入下一轮评审，是本文件的建议。

SoldComps.io当前公开文档列出美、英、德三站及各站原币。因此国际覆盖已是需要评估的竞争维度；公开页面不证明真实稳定性或商业许可。[官方API文档](https://www.soldcomps.io/docs)

## 2. 候选国家站点路线

| 批次建议 | 站点 | 研究币种 | 选择依据及解锁条件 |
|---|---|---|---|
| 当前V1 | 美国 | USD | 维持现有范围；来源、质量、成本和G0仍未通过 |
| 第一轮国际评审 | 英国 | GBP | 优先核对英语用户需求、独立来源权限、实际成交价和本地费项；达标后才确定开发顺序 |
| 第一轮国际评审 | 德国 | EUR | 与英国一起评估；需德语标题/日期/成色/版本字典、当地类目及独立质量证据 |
| 第二轮国际评审 | 加拿大、澳大利亚 | CAD、AUD | 根据实际客户所在地、查询量、有效样本密度及维护成本排序，不因英语站点默认低成本 |
| 后续欧洲评审 | 法国、意大利、西班牙 | EUR | 各自语言、分类、运费和覆盖独立验证；共享EUR不等于同一市场 |
| 独立平台路线 | Mercari等 | 依具体平台/地区 | 与eBay国际化单独评估，不共用访问许可或假定相同成交证据；不自动优先于eBay国际站点 |

该顺序是待客户/来源证据修正的建议，不给未获许可的站点承诺上线日期。英国或德国不可得时标记具体阻塞，并比较其他站点；不绕过访问限制。

2026-11-16用户确认的发布条件：每个新增站点同步交付当地所需语言，已存在语言复用并做地区适配。具体映射和验收见 [多语言专项](多语言与商业交付补充规格.md)；语言未就绪时不能仅开放数据站点。该条件更新后续评审标准，不提前解锁站点开发。

## 3. 国际能力必须准备什么

| 领域 | 必须满足的行为 | 当前契约影响 |
|---|---|---|
| 站点身份 | 明确平台、国家站点、来源；站点不等于卖家所在地或发货地 | 当前marketplace只开放ebay_us；后续按注册表定义稳定站点键，不临时添加不一致别名 |
| 币种 | 保留原币金额；先展示所选站点本地价格，换算展示明确汇率和日期 | 当前API按USD归一；增加本币输出时必须修订DTO/版本/fixture，不能直接改变既有cents字段含义 |
| 时间 | 保留当地原始日期、来源时区和精度；正确处理夏令时、模糊日期与日界线 | 沿用ADR-12时间原则，增加逐站夹具，不把国家直接映射成单一时区 |
| 属性和成色 | 本地类目映射、语言别名、尺寸/容量/版本及翻译差异可核验 | 每站维护清洗和匹配回归；不能只翻译UI而复用未经测试的属性规则 |
| 运费和税费 | 明确运费适用目的地和缺失状态；不把跨境运费、税、关税合并为确定到手价 | 保留item与已观测shipping两口径，新增税费能力另作契约 |
| 去重与覆盖 | 区分同一刊登的跨站曝光、重复观测及独立成交；披露时间/分页/样本覆盖 | 只在有稳定证据时合并事件，不把各站结果数直接相加当全球销量 |
| 查询和费用 | 站点参与规范参数、缓存键、幂等、owner复用和查询证据 | 未来新增跨站查询须另定额度/去重规则；不把“每站各一查”暗改成一次全站查询 |
| 权利与故障 | 每站独立准入、预算、熔断、时效、状态与停止分发 | 一站故障不让其他获准站点同时失效；不得通过改站点继续执行已被禁止的访问 |
| 用户入口 | 用户明确选择站点，看清币种/支持窗口/数据时间；不静默换站 | 网页、API、MCP一致；不支持站点明确拒绝，不回美国站数据冒充 |

V1仍是单站查询。未来多站对比先按站分别展示样本和统计；跨站合并统计要有相同属性、时间、费项、换汇及事件去重证据，不能仅汇率换算后取一个全球中位数。

## 4. 每站评审与开发工作包

以下为候选扩展工作，不是新TASK状态表；批准范围和依赖后再纳入唯一任务台账并复估人日。

1. 需求和准入：记录六类客户中实际需要该站的工作流、预算、访问/保存/展示/API分发范围和字段可得性。
2. 离线样本：构建逐站价格、日期、语言、属性、议价、运费、空页和挑战样例；禁止拿美站翻译样本冒充实源样本。
3. 适配与回归：在允许阶段实现源适配、taxonomy/匹配映射、幂等和事件身份；回归美国站，隔离站点异常。
4. 联网和成本验证：取得权限后连续观察，统计fresh且足量核验结果率、误配/误杀、实际价可得性、故障和维护成本；观测周期在该站评审时明确，不能沿用美国站PASS。
5. 契约和用户路径：定义本币/换算展示、站点支持信息、错误与费用；同步原稿、DEC、OpenAPI、SQL迁移、相关AT和界面。
6. 发布签收：来源权利、类目质量、成本、浏览器流程/API及非实现者复核分别留证；未达标站点保持未开放。

## 5. SoldBench与SoldStats的取舍

| 维度 | SoldBench | SoldStats |
|---|---|---|
| 直观含义 | 更像成交参考基准、比较与研究工具；Bench的含义需要副标题解释 | 更直接联想到已售统计、成交数据和价格分析 |
| 六类客户 | 可以覆盖卖家、商家、开发者与研究者，不由名字决定客群 | 同样可以覆盖六类；Stats不表示仅给一个中位数 |
| 产品预期 | 比较样本、基准、研究工作台 | 成交统计、分布、明细、筛选和分析；仍需说明研究对象 |
| 多国家站点 | 无天然限制 | 无天然限制；名字本身不证明全球覆盖 |
| 域名信息 | 用户此前表示soldbench.com可注册；未验证当前可注册性或归属 | 用户此前表示仅io/net/ai可选；未验证当前可注册性、价格或归属 |

判断：就用户目前强调的“多类客户、成交数据、价格研究和国际覆盖”而言，SoldStats语义更直接，我倾向其作为待选择品牌。SoldBench仍是合理候选，尤其创始人看重.com及基准研究含义时。二者差异不能替代真实用户理解测试；也不能为了保留旧建议而反向限制产品。

若选择SoldStats，io是符合数据/API产品表达的候选；net也可服务广泛用户；ai只有在AI确为核心体验时才较贴切。域名后缀的实际客户信任差异需要验证，不宣称某后缀天然带来增长。当前不据搜索结果确认可注册、品牌独占或商标可用。

可用一句定位测试理解度：“查真实成交，研究价格。” 向卖家/交易商/商家以及开发者/SaaS/专业用户展示相同功能介绍，分别检查是否理解用途、是否误认房地产工具、能否正确拼写和回忆品牌。少量访谈只作方向证据，不包装成统计显著的品牌胜负。

当前仍使用SoldBench作为项目名；用户明确选定后，再统一品牌、代码前缀、文档、域名配置和对外文案，不保留双重身份，也不暗示已经注册域名。
